# AI 账号管理系统完整开发提示词：本地管理与云端统一管理

> 使用方式：将本文全文交给负责开发的 AI／Agent。Agent 必须先读下方“执行总纲”，再执行第 0 节的询问和范围确认，再亲自完成所选分支的开发、部署、采集器和钩子安装、配置、真实数据联调与页面验证，按第 13.6–13.8 节提供保姆级带办流程。本文可以独立使用，不依赖原会话、原项目文件或原部署环境。
>
> 整理口径：以已有系统最终确认的功能、业务规则和采集链路为基准，覆盖多额度窗口、日／小时缩放、多人维护、标签、私人便笺及个人页面控制。账号文字放大属于最后一次静态预览调整，本文将其纳入目标界面要求，不据此声称原线上版本已经包含该调整。
>
> 通用化说明：本地独立部署、结构化外部账号绑定、标准快照接收接口及设备级授权，是供不同模式按需选用的设计要求；原有云端链路包含“本机钩子上传报告，再由云端任务回填应用”。这些通用化设计不能被误读为原系统已有的全部实现。新部署默认由采集器直接提交 JSON 快照，文件中转只是备选（见第 2.2 节）。本文不包含实际账号资料、服务器地址或登录凭据。
>
> 文中“原系统”“原基准”“原线上版本”等说法，指本文整理时依据的既有系统，只用来说明规则来源；执行时不需要、也无法访问它，一律以本文写明的规则为准。

## 执行总纲（先读这一页）

本页是全文的执行摘要。每次开始、恢复工作或进入新阶段时先读本页，再回到对应章节看细节；本页与后文不一致时，以第 0 节和第 13.8 节为准。

**你的角色：实施者。** 用户是决策者，只做选择、本人登录、授权和确认信任；安装、配置、排错和联调由你亲自完成。

| 阶段 | 你要做的事 | 用户要做的事 | 细节 |
|---|---|---|---|
| 1. 问清楚 | 按问法分级少问：先问必问项（个人＋本机通常只有 2 道），只读检测环境，再请用户确认检测结果 | 点选几道题 | 第 0.1–0.2 节 |
| 2. 确认范围 | 用大白话汇总，标明按推荐替用户定的事项，写入 `project-config.md` | 点一次“开始做” | 第 0.3–0.5 节 |
| 3. 开发 | 只做所选分支；随本文提供了参考实现时以它为基础，不重新从零开发 | 无 | 第 1–12 节、第 13.1 节 |
| 4. 装好跑起来 | 部署服务并托管进程，建立登录和设备连接，取得 Agent 访问凭据 | 本人登录、批准配对 | 第 3.3 节、第 13.5–13.6 节 |
| 5. 接通真实数据 | 探测并核实数据来源，安装采集器和所选的自动更新方式 | 必要时确认信任钩子 | 第 8 节、第 13.3 节 |
| 6. 走通一遍 | 真实采集 → 直接提交到管理服务 → 入库 → 接口读回 → 打开页面核对 | 无 | 第 9 节、第 13.6 节 |
| 7. 交付验收 | 按状态表如实报告，交付大白话教程 | 看结果、提意见 | 第 13.7–13.8 节、第 15 节 |

**任何阶段都要守住的规则：**

1. 跟用户说话一律用大白话；问题 ID、接口名和字段名只写进配置和技术文档。
2. 只做用户选定的范围，不擅自扩大，也不悄悄缩小；会改变数据去向、身份范围或发布目标时先问。
3. 数据必须真实：拿不到就标“未知”或“待接入”，不编造数值，不把模拟数据当真实数据，不把文件修改时间当观测时间。
4. 状态如实：只有源码不等于已安装，已上传不等于已入库，已入库不等于页面已显示。按第 13.8 节状态表报告，没有证据的阶段不算成功。
5. 秘密不进聊天、日志、文档和安装包：密码、令牌、Cookie 和认证文件正文一律不索要、不打印、不保存。
6. 命令由你亲自执行并检查结果；普通报错自己排查修复，只把真正需要本人做的那一步交给用户，并说清“卡在哪、只做哪一步、做完你怎么接着干”。
7. 范围确认后，进度和决定写进项目文件：配置写 `project-config.md`，安装和联调进度写 `docs/安装与联调记录.md`。上下文被压缩、会话中断或换了新会话时，先读这两个文件和本页，再从未完成的步骤继续；不以 AI 工具自带的记忆功能作为本项目配置和进度的依据。
8. 进入每个阶段、开发每个模块之前，回到对应章节重读一遍，不凭印象实现；完成后对照第 14 节的对应场景自查。

## 0. 先用内置选择框完成配置，再开发和验收

本节优先于后文的“必须实现”“完整交付”等表述。后文描述完整功能基准及不同部署分支，不表示每个用户都要开发所有分支。未选择的模式不作为本次缺失功能，不为了满足后文列表擅自扩大范围。

完整流程是：**内置选择框分批询问 → 按答案追问 → 汇总配置并确认 → Agent 开发系统 → Agent 部署并启动 → Agent 安装采集器和钩子并配置连接 → Agent 提取、上传、入库和回读真实数据 → Agent 打开页面核验 → 用户验收／反馈修正 → 交付可用系统**。选项用于确定实现和运行方式，不让用户逐项重新勾选已有核心功能。

**执行责任：Agent 是实施者，用户是决策者和必要授权者。** 默认任务目标是“帮用户装好、配好并跑通”，不是“做几个安装包让用户自己安装”。安装包、源码和教程是可复用产物，不能代替 Agent 在已确认且可访问的目标环境亲自执行安装与验证。用户若明确只要方案或离线分发包，再记录为范围例外；不能主动把完整安装目标缩减为发包。

### 0.1 交互规则与第一批选择

**优先实际调用当前会话可用的内置选择框／问答卡片工具，让用户直接点选。** 不要仅在普通回复中写“请选择 1、2、3”，也不要输出一段工具调用 JSON 冒充已经打开选择框。

具体规则：

1. 先复用当前对话中已经明确的选择，只问尚缺的内容。不得因为用户换了话题再让他重复填写。
2. 调用当前 AI 工具实际提供的选择框／提问工具（不同工具名称不同，以当前可用的工具列表为准）；若某个选择工具只允许在特定模式下使用，就遵守限制，不为显示选择框擅自切换会话模式。
3. 工具名、参数和选项数量以实际工具为准，不能臆造不存在的工具或 API。若内置选择框不可用，简短说明后才退回对话中的编号选项，不声称已显示弹窗。
4. 每批通常 1–3 个问题，每题通常 2–4 个互斥选项，服从工具上限。选项用短标题，加一句大白话说明选了会怎样；仅在上下文足以判断时标注“推荐”。措辞按本节下方的“问法要求”。
5. 需要多个操作系统等多选信息时，若工具不支持多选，就拆成单选问题，或提供“好几种系统都要”这类选项，再用文本输入补问具体范围；不能让单选框承担多选语义。
6. 保留工具自带的自由填写能力，允许用户说明特殊情况；工具已经有“其他”输入时不要重复添加同名选项。
7. 发出问题后等待实际回答；异步工具返回不等于用户已选。预选、超时、示例和沉默都不算选择或授权。用户取消某批问题时先处理取消意图，不自行采用首项。
8. 本节描述的是未来使用本提示词时的配置过程，不要求编辑提示词的 AI 此刻向用户展示整套配置问卷。
9. 模式未选定前不创建项目、不开发、不部署。选定后可做必要的只读环境检测，结果用于补齐配置；写入和搭建等待第 0.3 节确认。
10. 不通过选择框索要密码、令牌、Cookie 或认证文件正文；真实授权使用部署环境的安全配对／凭据机制。
11. 已确认的常规下载、解压、依赖准备、安装、写配置、启动、联调和排错由 Agent 使用可用工具执行。需要本人登录、扫描配对码、通过系统授权或信任钩子时，只交给用户那一个必要动作，完成后 Agent 接着干，不把后续安装步骤整套交还给用户。
12. 开工前用一两句大白话提前告诉用户：接下来 AI 工具可能会弹出“是否允许”的确认，这是工具自带的安全提醒，说明大概会在哪些步骤出现、怎么判断该不该点。按当前工具的实际机制说明，不替用户更改安全设置，也不劝用户关闭全部确认；同类操作尽量合并执行，减少弹窗次数。需要系统管理员密码时，说明用途，请用户在系统自己的密码框或终端里输入；Agent 不在聊天里索要密码，也不记录密码。

**问法要求：说大白话。** 回答问题的人不一定懂技术。选择框里的每句话都要让外行一看就懂，像同事当面问你一样自然：

- 标题直接问对方的情况或想法，例如“这个系统是你自己用，还是团队一起用？”，不要写成“请选择管理模式”。
- 选项名用日常说法；后面那句说明只讲“选了对你有什么不同”，不讲内部怎么实现。
- 问题 ID、接口名、字段名和文件名只供内部记录，不出现在选择框和给用户的说明里。
- 尽量不用术语，前端、后端、API、数据库、部署这类开发用语也换成“页面”“后台”“装好跑起来”等说法；实在绕不开时，括号里补一句大白话，例如“用 AI 时自动更新（技术上叫 Hook）”。常用说法见下表。
- 第 0 节各表中，“选择框标题”和“选项（给用户看）”就是推荐说法，可以按上下文微调，但不能改回术语，也不能改变选项含义。“对应配置与处理”“对应动作”两栏按顺序对应左边的选项，用来记录配置值和指导实现，只给 AI 看，不原样贴给用户。
- 需要用户补充文字时（文件夹、时间、系统等），同样口语化并给个例子，例如“每天几点补查一次？比如晚上 11 点”。
- 说检测结果时同样口语化：用户自己认得的名字（例如他在用的 AI 工具）可以直接说；文件名、配置项、端口号这类内部名称，换成用户能理解的说法，例如“你电脑上那个切换账号的脚本管着 9 个账号”。
- 每轮小结、最终配置摘要、冲突说明和验收结果都按同样标准写。

| 文中说法 | 跟用户这样说 |
|---|---|
| Hook、会话事件触发 | 用 AI 的时候自动更新 |
| Hook 宿主 | 你用的 AI 工具 |
| 定时补漏、定时任务 | 到点自动再查一遍，补上漏掉的 |
| 采集器、采集适配器 | 自动读取账号用量的小工具 |
| 来源 | 要读取数据的 AI 服务 |
| 回环地址、本机预览 | 只有这台电脑自己能打开 |
| 内网 | 公司（或家里）的内部网络 |
| 结构化直传 | 数据直接发给系统 |
| 报告中转、收集区 | 先把报告文件传上去，系统再定时去取 |
| 隔离适配器、隔离联调 | 先用模拟数据把流程跑通 |
| 设备配对、设备授权 | 第一次连接时确认一下这台电脑，之后就认得它了 |
| 共同维护人、关联者 | 负责这个账号的人 |
| 幂等、去重 | 同一份数据重复发，也只记一次 |

**问法分级：能检测的不问，有默认值的不逐题问。** 第 0 节各表是完整选项库，用来统一措辞、记录配置和处理用户改选，不是要逐题弹出的问卷。按下表分级处理：

| 分级 | 怎么处理 | 适用的问题 ID |
|---|---|---|
| 必问 | 只有用户知道、又没有安全默认值的，用选择框问 | `management_mode`、`deployment_mode`；云端或团队内网分支的 `hosting_target`；需要跨设备访问时的 `access_scope`；团队分支无法从已有平台判断时的 `auth_mode` 和初始管理员；双模式的 `dual_mode_data` |
| 检测后确认 | 先只读检测，再用一句大白话说出发现，请用户确认或纠正；检测已能确定的不再单独出题 | `project_origin`、`collector_platforms`、`device_scope`、`installation_access`；`collection_basis` 与 `source_scope` 合并成一题，例如“我在这台电脑上找到了两个 AI 工具，要把它们的账号都接进来吗？”；`initial_data` 只在找到疑似旧数据文件或用户提到旧数据时才问 |
| 默认值 | 不逐题问，按推荐值写进第 0.3 节汇总并标明“按推荐帮你定了”，用户可通过“我想改几项”修改；表中没有标推荐的，取用户操作最少、又不会把数据送到新地方的选项，例如 `development_flow` 取“直接全部做完”，`backup_policy` 取“自动备份到本机或公司内部” | `ingestion_mode`、`sync_strategy`、`sync_parameters`、`history_policy`、`backup_policy`、`development_flow`、`release_scope`；团队分支的 `visibility_policy`、`member_management` |

个人＋本机的常见情况，开工前一般只要 3 轮：第一轮问 2 道必问题，第二轮确认检测结果，第三轮确认汇总。用户主动想自己定某一项，或者检测结果和默认值对不上时，再从选项库调出对应问题。

第一批只问下表前两题，已知项跳过；`project_origin` 能从用户消息或当前目录判断时不问，判断不了再用第三行的说法问：

| 问题 ID | 选择框标题 | 选项（给用户看） | 对应配置与处理（只给 AI 看） |
|---|---|---|---|
| `management_mode` | 这个系统是你自己用，还是团队一起用？ | **我自己用**：只有你自己登录，照样能管好几个账号、好几台电脑；**团队一起用**：好几个人各自登录、一起管账号，每人能看什么、能改什么可以分开设 | **个人管理**：只有本人使用，可管理多个账号和设备；**团队管理**：多人登录，共同维护并区分权限 |
| `deployment_mode` | 系统打算放在哪儿运行？ | **放在本地**：就放在你自己的电脑，或公司内部的机器上；**放到云上**：放在云服务器或现成的线上平台上；**两种都要**：本地一套、云上一套，两套都做 | **本机／团队内网**：自己的电脑或内部设备；**云端**：服务器或应用平台；**本地和云端都需要**：明确开发两种部署方案 |
| `project_origin` | 是从零做一个新的，还是在你现有的项目上改？ | **从零做新的**：新建一个文件夹，从头开始做；**在现有项目上改**：先看看你现在的代码，原来改过的地方都会保留；**还没想好**：我先讲讲两种有什么区别，你再定 | **新建独立项目**：在新目录开发；**改造已有项目**：先检查已有代码并保留原改动；**暂不确定**：先说明选择影响，再确认目录与范围 |

管理方式和部署位置相互独立：个人也可以使用云端，团队也可以部署内网。不得把某一项替用户自动推导成另一项。

### 0.2 按分支展示后续选项

以下是选项库，按第 0.1 节的问法分级使用：必问项用选择框问，检测后确认项先检测再请用户确认，默认值项写进汇总、不逐题问。各表“何时询问”一栏只说明该题适用的前提，是否真的弹出选择框以问法分级为准。需要提问时每批 1–3 题；已知、不适用及无需用户决策的技术细节跳过。每轮用一两句大白话说明目前定下来的内容，例如“目前定了：你自己用，放在这台电脑上”，允许用户直接修正。

#### A. 运行环境与设备范围

| 问题 ID | 何时询问 | 选择框标题 | 选项（给用户看） | 对应配置与处理（只给 AI 看） |
|---|---|---|---|---|
| `collector_platforms` | 存在本地采集时 | 读取账号用量的小工具，要装在哪种电脑上（Windows、Mac 还是 Linux）？ | **跟这台电脑一样**（一般推荐）：我自动认一下这台是哪种；**换一种**：比如这台是 Windows，但要装到 Mac 上；**好几种都要**：比如 Windows 和 Mac 都要用 | **仅当前系统**（通常推荐）：检测当前运行环境；**指定另一系统**：补充目标系统；**跨系统**：补充实际需要支持的系统，按范围制作安装包 |
| `device_scope` | 设备范围未明确时 | 要读取几台电脑上的账号数据？ | **就这一台**：只管现在这台电脑；**我自己的几台电脑**：比如公司电脑和家里电脑都要；**团队成员的电脑**：每个成员的电脑都装上 | **当前一台设备**；**本人多台设备**；**团队多台设备**（仅团队分支）；据此决定配对、来源区分和接入说明，不虚构实际设备数 |
| `hosting_target` | 云端或团队内网分支 | 系统具体放在哪台机器或哪个平台上？ | **放到现有的平台上**：我接进你已经在用的平台，并装好验证；**装到指定机器上**：你确定机器后，我负责安装和配置；**还没确定机器**：先帮你把能准备的做好，接通目标后继续装，不算已经全部完成 | **接入现有应用平台并实际部署**；**部署已确认的服务器／内网主机**；**目标环境待定**：先完成不依赖目标的工作，记录待接通项，不默认退化为仅交付包，也不擅自购买资源 |
| `access_scope` | 服务需要跨设备访问时 | 要在哪些地方能打开这个系统？ | **只在公司或家里的网络里**：连着同一个网络才能打开，外面打不开；**在外面也要能打开**：通过你们已经允许的远程方式，比如公司 VPN；**还没想好**：先只在这台电脑上打开看看，以后再定 | **仅内部网络访问**；**通过已授权远程入口访问**；**尚未确定，先保留本机预览**；不能因选择云端就自行向公网开放 |
| `installation_access` | 目标设备／平台尚不能执行安装时 | 我现在能连上要安装的地方吗？ | **已经连好了**：我先核实能不能操作，接着直接安装；**需要先连一下**：你按提示完成一次连接或授权，我来检查；**有些机器现在不在线**：先把在线的装好，其他的记下来，连上后由那台机器上的 AI 接着装 | 复用可信终端、平台或远程执行通道；必要时引导建立配对；逐设备记录执行位置和状态，不把本机命令当成另一设备的安装结果 |

操作系统、目录、服务器地址及现有平台名称若已提供就直接复用；否则只读检测能够确定的信息不反复问。先选概念，再按需补充目录或主机等少量文本信息。

#### B. 账号数据从哪里取得、如何上传

| 问题 ID | 何时询问 | 选择框标题 | 选项（给用户看） | 对应配置与处理（只给 AI 看） |
|---|---|---|---|---|
| `collection_basis` | 首批来源能力未明确时 | 账号的用量数据从哪儿来？ | **用我已有的脚本**：你已经有自动读取用量的脚本，接着用，我先看看它能做什么；**重新做一个**：我先看看这台电脑上能读到哪些数据，再做个新的自动读取工具；**先导入手头的表格或报告**：先把已有数据导进来，之后要不要自动读取再单独问你 | **复用已有 Hook／采集脚本**：先检查能力；**开发新的采集接入**：检测本机接口和缓存；**先导入现有报告／表格**：建设导入与匹配，并明确自动采集是否仍待接入 |
| `source_scope` | 未明确首批来源时 | 一开始要接几种 AI 服务的账号？ | **先接一种**：先把一种 AI 服务接好，别的以后再加；**一次接好几种**：一开始就把要用的几种都接上；**暂时还接不上**：先用模拟数据把系统和流程跑通，真实账号以后再接 | **先接入一个来源**；**首批接入多个来源**；**来源尚未具备，先用隔离适配器联调**；来源保持“服务 A／B”等中性名称，不因能扩展就承诺支持任意真实来源 |
| `ingestion_mode` | 设备连不上管理服务，或用户明确要求中转时 | 读到的数据怎么送到云上的系统？ | **直接发过去**（推荐）：读完马上发给系统，很快就能看到；**先传文件，再定时导入**：先把报告文件传到云上一个专门的文件夹，系统定时去取，会晚一会儿，一般只在电脑连不上系统时才用；**两种都要**：两条路都做，分别测一遍 | **结构化直传**（默认）：Hook 采集后直接调用接收接口；**报告中转**：先上传文件，再由统一任务回填，仅在第 2.2 节所列情况采用；**两条都要**：分别实现和验收 |
| `sync_strategy` | 需要自动更新时 | 账号数据什么时候自动更新？ | **用 AI 时更新，再定时补查**（推荐）：每次用 AI 时自动更新，另外到点再查一遍，补上漏掉的；**只在用 AI 时更新**：不另外定时；**只按固定时间更新**：到点自动查，跟用不用 AI 无关 | **Hook＋定时补漏**（宿主支持时推荐）；**仅 Hook**；**仅定时**；按能力实施，始终保留主动同步／重试入口 |
| `sync_parameters` | 需要明确自动化参数时 | 多久自动查一次？ | **按推荐来**：主动读取时两次至少隔半小时，读取已有缓存时有新数据才处理；**我自己定**：你来定多久查一次、每天几点补查，接下来再问具体时间 | **采用推荐参数**：实时型至少 30 分钟、缓存型有新数据才处理；**自定义频率／补漏时间**：补问时间、时区及间隔；无法满足来源或平台限制时解释后重新选，不强行承诺 |

本机分支直接提交本机服务，团队内网分支由成员设备直传内网管理服务，云端分支同样默认直传云端接收接口；三种情况都不需要文件收集区，只有设备连不上管理服务时才考虑文件中转。推荐值须显示在最终配置中获得确认，不能把默认值冒充用户已经选过。

选择“仅定时”时，不向用户的实际宿主安装或启用未选择的 Hook；第 8 节中与事件入口相关的运行验证标记不适用。选择“仅 Hook”时不创建补漏任务。需要安装或启用实际定时任务时，目标、时间、时区和运行环境必须已经明确。

需要真实适配时核实本机接口、缓存格式或用户已有脚本。来源尚未具备时允许完成应用和隔离联调，但必须记录真实采集／真实发布待接入，不能把测试适配器标成真实账号接入完成。

#### C. 人员身份、可见范围和共同维护

个人分支使用稳定的本人身份及显式管理员初始化，跳过员工目录和团队授权问题；云端个人版仍需要可靠的登录和设备配对。

团队分支按需询问：

| 问题 ID | 选择框标题 | 选项（给用户看） | 对应配置与处理（只给 AI 看） |
|---|---|---|---|
| `auth_mode` | 大家用什么账号登录这个系统？ | **用现在平台的账号**（推荐）：系统放在哪个平台上，就用那个平台的账号登录；**单独开账号**：在这个系统里给每个人单独开账号；**用公司统一登录**：用公司现有的统一登录方式进来 | **复用现有平台身份**（已有平台时推荐）；**应用独立用户体系**；**现有统一身份系统**：需核实实际接入协议，不假定兼容 |
| `visibility_policy` | 团队成员能看到哪些账号？ | **团队的账号大家都能看**：但只有负责这个账号的人和管理员能改；**只能看自己负责的**：每个人只看得到自己负责的账号；**按人或分组单独定**：接下来再问具体规则 | **团队业务账号均可查看**：沿用本文基准，仅关联者和管理员可写；**仅本人关联账号可见**：需调整全部读接口、通知和导出的授权；**自定义人员／分组范围**：补充明确规则后开发 |
| `member_management` | 每个账号由谁负责，谁能改这份名单？ | **只有管理员能改**（推荐）：谁负责哪个账号，统一由管理员来定；**再指定一些人也能改**：接下来再问是哪些人、能改到什么程度 | **仅应用管理员**（本文基准，推荐）；**指定管理角色**：补充角色和可操作范围；无论哪种，采集器不得自行加成员 |

初始管理员的可信身份尚未明确时，补问应由谁在初始化阶段认领或复用哪个已核验平台用户，问法如“系统的第一个管理员由谁来当？是你自己吗？”。不能根据姓名猜 ID，也不能把首次打开页面的任何人自动提为管理员。

“仅本人可见”针对业务账号列表，不表示可以读取别人的私人便笺。私人便笺、贴纸位置和单页控制始终属于本人，不随共享策略放宽。

#### D. 已有数据、历史与备份

| 问题 ID | 何时询问 | 选择框标题 | 选项（给用户看） | 对应配置与处理（只给 AI 看） |
|---|---|---|---|---|
| `initial_data` | 存在旧记录或启动方式未明确时 | 以前的账号数据要带过来吗？ | **从空白开始**：不带旧数据，从零开始记；**导入表格或报告**：把手上的表格、报告导进来，导之前先给你看会改哪些；**从旧系统搬过来**：把以前在用的系统里的数据整个搬过来，原来的记录都留着 | **空库开始**；**导入表格／报告**；**迁移已有系统**；导入／迁移先预览差异，保留旧标识、绑定与历史，不直接覆盖 |
| `history_policy` | 用户有容量或历史要求时 | 以前的使用记录要留多久？ | **全部留着**（建议）：所有历史都保留，随时能查；**旧记录定期收起来**：超过一段时间的挪进归档，平时不显示，需要时还能找回，接下来再问留多久 | **保留全部业务历史**（默认建议）；**按期限归档**：补充期限与恢复要求；删除重要历史须另有明确范围，不能把归档等同物理删除 |
| `backup_policy` | 确定运行环境后 | 数据要怎么备份？ | **需要时让 AI 帮我备份**：你说一声，AI 负责执行和检查；**自动备份到本机或公司内部**：我配好定时备份；**自动备份到云存储**：我配到你指定的位置 | **Agent 按需执行备份／恢复**；**Agent 配置并试跑本地／内网定时备份**；**Agent 配置并试跑指定云存储备份**；补充频率、目的地及保留策略，不未经授权外传数据 |
| `dual_mode_data` | 明确选择本地和云端两种部署时 | 本地版和云上版的数据要不要打通？ | **各管各的**：两边数据互不相干；**搬一次就行**：把一边的数据一次性搬到另一边，之后各自独立；**一直保持同步**：两边始终保持一致，接下来要问以哪边为准、两边都改了听谁的 | **数据相互独立**；**一次迁移**；**持续同步**；持续同步须补充主数据源、方向和冲突策略，不把一次导入当作持续同步 |

无需每个用户单独选择历史保留策略：没有特殊要求时，将“全部历史保留、无自动删除”作为待确认建议放入最终配置即可。备份不包含明文凭据，恢复必须保留账号、成员、版本和私有内容隔离。

#### E. 开发节奏和实际交付

| 问题 ID | 何时询问 | 选择框标题 | 选项（给用户看） | 对应配置与处理（只给 AI 看） |
|---|---|---|---|---|
| `development_flow` | 未给定开发节奏时 | 想先看看界面样子再做，还是直接全部做出来？ | **先看界面样子**：先做一版能看的界面给你确认，满意了再把整套做完；**直接全部做完**：直接把整套做好，做完你再试用、提意见 | **先静态预览，再完整实现**：样例仅用于界面确认；**按基准直接完整开发**：完成后验证与反馈；两者都交付选定范围的完整系统，不能停在静态稿 |
| `release_scope` | 实际安装目标尚未明确时 | 这次要帮你装到哪些地方？ | **只装好这台电脑**：系统和读取账号的小工具都由我装好；**装好服务器和这台电脑**：我把线上系统和本机自动更新一起接通；**装好服务器，再接入多台电脑**：先确认机器名单，能连接的由我逐台处理，不能连接的交给对应电脑上的 AI 接着装 | 按所选模式确认实际服务端和客户端目标；Agent 亲自完成可访问目标的安装、配置与联调，逐目标给出证据；目标已在前面确认时跳过本题，不再提供“仅代码＋安装包”作为默认终点 |

默认采用本文完整功能基准，不再逐项追问要不要日历、额度、标签、便笺、页面控制或导出。布局参数和内部技术栈由 AI 按基准实现，不让用户选择没有业务影响的每个库和数据库参数。

### 0.3 汇总配置，用内置选择框确认开始

在关键选择明确、依赖没有冲突后，先输出一份可检查的简短配置摘要，覆盖：

1. 个人／团队、目标设备范围、实际已知的用户和设备规模。
2. 本机／内网／云端／双模式、项目起点、源码目录和运行环境。
3. 身份来源、初始管理员、团队业务读取范围及成员管理规则。
4. 采集来源、Hook／定时策略、同步参数、直传／中转及目标地址范围。
5. 导入／迁移、历史保留、备份及双模式数据关系。
6. 本文基准的核心功能、适用的团队能力、开发节奏和交付目标。
7. 采用的建议默认值、不适用分支、待检测项及当前无法真实验收的事项。
8. Agent 具体会安装到哪些设备／平台、要启用哪些后台服务或任务、使用哪种已授权执行通道；用户仅需完成哪些本人登录或确认动作，包括 AI 工具可能弹出的“是否允许”确认和系统密码输入（见第 0.1 节第 12 条）。

摘要是给用户看的，按“问法要求”写：每条一句大白话，先说结论，例如“谁用：你自己”“放哪儿：这台电脑”“数据怎么更新：用 AI 时自动更新，每晚再补查一次”；按推荐替用户定的、这次用不上的、要等真实环境才能测的，各用一句话点明。问题 ID 和技术细节记入配置文件（见第 0.4 节），不堆在摘要里。

随后实际调用内置选择框，标题如“就按这些设置开始做，可以吗？”，提供：

| 选项（给用户看） | 对应动作（只给 AI 看） |
|---|---|
| **没问题，开始做吧**：就按上面这些开工，包括按推荐帮你定的几项 | **确认配置并开始开发**：接受摘要及列明的建议默认值，进入已选范围的实现 |
| **我想改几项**：你先选要改哪一块，我只重新问相关的问题 | **修改部分选择**：先选需要修改的类别，仅重问对应项及受其影响的下游项 |
| **先说说打算怎么做**：我先给你一份做法说明，你点头了再动手 | **先查看实施方案**：只输出方案，待用户明确确认开始后再实现 |

明确同意后开始开发。若用户已经在同一条消息中说明完整选择并明确要求“直接开始”，视为已确认，简要说明采用的范围后继续，不再重复索要确认。若缺少会改变权限、数据去向或真实发布目标的关键答案，不能用“直接开始”替用户猜测这些答案。

摘要中的“开始做”应明确包含已列出的部署、安装、配置和验证；在现有授权及工具权限内连续完成，不每执行一条正常命令都再问一次。具体平台、系统和工具仍要求审批或本人确认时如实处理，不能把范围确认当作绕过审批、任意提权或覆盖未指定正式系统的许可。

环境未具备时可以确认一个缩小且可验收的当前阶段，例如“完成应用和隔离测试，暂不连接真实来源”，同时保留后续目标。不能把真实接入未完成改写成整个系统已验收。

### 0.4 把选择转换为功能范围

| 能力 | 个人管理 | 团队管理 |
|---|---|---|
| 多账号、多个额度池、日／小时日历、Tokens、订阅、重置券、备注 | 全部保留 | 全部保留 |
| 标签、反向筛选、人名贴纸、私人便笺、个人页面控制、导出、在线 GUIDE | 全部保留；人名贴纸仍是分类标记 | 全部保留，按用户和权限隔离 |
| 维护人和权限模型 | 使用稳定的单人身份及管理员能力，保留可扩展关系模型；隐藏无意义的人员筛选和管理入口 | 启用多对多共同维护、与我相关、成员管理、权限点和已选读取范围 |
| 成员与权限维护 API | 不要求交付供多人使用的操作流程；已存在的接口也必须受权限保护 | 按第 3 节及已确认身份／管理角色实现并验收 |
| 部署、传输、采集触发、备份、安装与验收 | 仅实现已选分支；未启用功能不在设备上安装或运行 | 同样按已选范围执行 |

个人管理不等于只管理一个 AI 账号，也不能删除日历、标签、便笺或用量等核心功能。未启用的团队能力保留必要模型扩展点，不强制用户配置员工、组织目录和共享服务器。

范围确认后，将配置保存到项目说明或独立的 `project-config.md`。每项记录值、来源（用户选择／显式要求／检测结果／已确认建议）、适用状态及确认时间，至少覆盖上述问题 ID；接入真实来源后补充第 8.5 节的“来源适配记录”。未确定或不适用项明确标记，不能伪装成已经完成的用户选择。

### 0.5 依赖检查、变更和验收闭环

确认前检查组合是否可运行：

- “仅本机回环”却要求其他设备直连，需要改选可访问的内网／远程目标，或限定当前阶段，不自动扩大网络开放范围。
- “报告中转”缺收集区或处理任务，需要确认现有设施、新建范围或暂缓真实接入。
- 设备连不上云端接收接口时，先通过已授权的远程入口（例如公司 VPN）或调整服务的访问范围解决，再考虑报告中转；不为此擅自向公网开放服务。
- “仅 Hook”但宿主没有事件能力，给出更换触发方式或先交付待接入适配器的选择，不伪造钩子。
- “云端定时任务”需要读取本机文件时，把采集留在本机运行；云端只处理已上传数据。
- “复用平台身份”但目标不是该平台，需要先核实认证支持或改选独立身份，不能只信任客户端传来的用户 ID。
- “本地和云端持续同步”需要明确主数据源和冲突处理，未确认前不得擅自开启双向写入。
- 收紧业务读取范围时，必须联动 API、列表、详情、标签、统计、导出、缓存与事件通知，不只隐藏前端行。

向用户说明这类冲突时不照搬上面的技术说法，用大白话讲清哪两项对不上、各会怎样、可以怎么选。例如：“你选了只在这台电脑上打开，又希望别的电脑也能连上来，这两项对不上。是改成在公司网络里都能打开，还是这次先只在这台电脑上用？”

用户改选时保留不受影响的答案，将失效的下游项标记待确认。例如从个人改为团队后补身份和权限，从云端改为本机后不再强制询问公网域名和云端收集区。只重新确认受影响的范围，不让用户整套重填。

开发中按配置推进，普通实现细节不反复确认；发现来源能力与已确认预期不符，说明证据、影响和可行选项后再决定受影响部分。不得悄悄把真实采集换成演示数据或换另一条传输路径。

验收时附“配置要求—实现—验证结果”对照表，明确已通过、失败、待真实环境验证和不适用；给用户看的结论用大白话，如“通过了”“没通过”“要等真实环境才能测”“这次不涉及”，各跟一句原因。提供与实际阶段一致的内置选择，标题如“这次做的东西，你看行不行？”：

| 选项（给用户看） | 对应动作（只给 AI 看） |
|---|---|
| **可以了，就这样**：这次的交付就算完成了 | **验收通过，完成当前交付** |
| **还要改改**：你说说哪儿不对，我改完重新测一遍再请你看 | **需要调整**：收集具体问题，修复并重跑相关验证，再请求验收 |
| **接着做下一步**：我先说清下一步在哪儿、做什么，你同意了再继续 | **继续下一阶段**：仅在确有已说明的下一阶段时提供，先列明具体环境和动作，按用户选择继续；不自动发布到未授权环境 |

用户没有回复时不能写“用户已验收”。默认按第 13.8 节先完成实际安装和联调，再交付已验证结果并说明待用户反馈，不通过无限等待阻塞交付。只有用户明确将当前阶段限定为开发、自测或方案时，才按该阶段交付并保留真实安装待办。已有明确发布授权时完成授权范围内的发布和验证，不把流程机械地变成重复审批。

## 2. 两种运行模式

本节为分支规范，只实现第 0 节选定的部署模式和上报路径。“本地／云端”与“个人／团队”独立组合，不能仅因阅读了本节就自动扩大交付范围。

### 2.1 本地账号管理

适用于个人电脑，也可用于已确认的团队内网部署。个人默认回环访问；团队内网分支必须配置多人认证、服务访问范围及成员设备接入方式。

必须实现这条完整链路：

```text
本机 AI 工具发生会话事件
→ 本地 Hook 快速登记触发
→ 后台采集器读取当前登录账号及实际可得数据
→ 校验账号身份、规范化快照
→ 直接提交本机管理服务
→ 业务规则校验并写入本地数据库
→ 本地页面接收更新提示并重新查询
```

具体要求：

- 个人本地管理服务默认仅监听回环地址，浏览器访问本地服务；也可用桌面外壳承载同一前端。团队内网模式仅开放用户确认的内网地址和认证访问。
- “本地直传”是采集器直接调用本机接收／业务接口；团队内网模式则直传已确认的内网管理服务。两者均无需先上传云端收集区，也无需经过云端 Agent。
- 采集器不得绕过业务规则直接写数据库；同进程调用也必须经过等价的身份、校验和事务入口。
- 纯静态 HTML 无法独立完成任意本机文件读取、后台钩子、持久数据库和安全接收；交付中必须有本地服务或桌面宿主。
- 默认不向外部服务器上传账号资料。本地软件可按实际适配器需要访问获授权的数据源，必须区分“查询账号数据”和“上传管理数据”。
- 本地数据持久保存，浏览器关闭或机器重启后仍保留；提供备份和恢复步骤。只有用户选择云端迁移或双模式时才交付迁移流程。
- 单人模式建立稳定的本地用户身份，保留成员表、权限点和私有资源模型；不能为了单机省事而删除多人能力的数据结构。
- 若启用本地多用户或局域网访问，必须显式配置认证与访问范围；不能把回环模式的默认信任直接扩展到网络。
- 采集器到本地服务使用首次配对生成的受限凭据或等价安全机制，并校验 Host／Origin 等边界，不能允许任意网页向本机服务写数据；Agent 调用本地服务使用第 3.3 节的 Agent 访问凭据，同样不能免认证。
- 用户切换被管理账号时，重新核对外部账号身份；不得把新账号额度写到上一账号。

### 2.2 云端统一管理

适用于个人多设备或团队多人员、多设备将账号状态汇总到同一应用。

以下给出直接入库和报告中转两条接入基准，共用同一套业务规则。**默认只实现路径一。** 路径一提交后立即可查、字段完整、环节少；设备断网时由本地待发队列保存，恢复后自动补发（第 9.5 节），不需要靠云端文件夹缓冲。路径二多出收集区、扫描任务、处理台账和文件命名等环节，入库有延迟，只在下列情况实现：设备确实连不上管理服务，且无法通过已授权的远程入口（例如公司 VPN）解决；需要兼容已有的、只会产出报告文件的采集器；或用户明确要求保留文件中转。明确选择两条都需要时才同时交付。

路径一：结构化快照直传。

```text
使用者设备的 Hook
→ 本地后台采集器
→ HTTPS 云端快照接收接口
→ 验证设备、操作者、数据归属和账号绑定
→ 校验、幂等、版本及数据新鲜度处理
→ 云端数据库
→ 页面自动同步
```

路径二：先上传报告，再统一回填。

```text
使用者设备的 Hook
→ 本地采集并生成报告文件
→ 上传到有访问控制的云端收集区
→ 云端任务／获授权 Agent 检查新增文件
→ 解析报告并匹配已有账号
→ 调用应用业务 API 入库
→ 写入处理台账和读回结果
→ 页面自动同步
```

具体要求：

- 云端不能直接假定能读取员工电脑文件。采集必须发生在具备访问条件、并已获授权的本机环境。
- 云端处理已上传报告时，不能使用云端自身登录的 AI 账号重新采集并替换报告内容。
- 快照必须能区分上传主体、来源设备、外部账号以及采集时间；上传者与账号共同维护人不是同一个概念。
- 每台设备有独立、可撤销的采集授权，权限限制到已配对人员／账号及允许写入的数据类型。
- 普通上传不能添加共同维护人、转移账号归属、修改应用权限或覆盖人工备注。
- 支持中央收集者汇总多台设备数据，但必须使用显式授权的设备和账号映射，不能把中央上传身份自动认定为所有账号的维护人。
- 文件中转入库任务可配置周期，例如每个整点和半点执行；直传模式提交成功后立即可查询。界面和文档说明两者延迟差异。
- 云端平台调度器的实际最小周期以部署环境能力为准，不把某个示例周期写成所有平台的保证。
- 支持本地完整采集任务定时补漏，例如每天指定时间补充延迟返回的日用量；本机任务只有在设备开机、联网及相关运行时可用时才能工作。
- 保持收集报告历史与处理台账，业务入库只保留每个额度池每个周期的有效记录；不要把“每份新报告”当成“新额度周期”。

### 2.3 两种模式的共同边界

下表对比两种部署方案；数据库按已选方案和实际规模确定。团队内网本地部署的网络目标为内网服务，采集位置为各成员设备，不局限于当前电脑。

| 项目 | 本地模式 | 云端模式 |
|---|---|---|
| 页面与业务规则 | 共享 | 共享 |
| 数据库 | 默认本地 SQLite | 默认 PostgreSQL |
| 用户身份 | 本地配对身份，可升级多用户 | 可信平台会话或独立认证会话 |
| 采集位置 | 当前电脑 | 每位使用者的设备 |
| 传输目标 | 回环地址上的本地服务 | HTTPS 云端接收接口；设备连不上时才用收集区 |
| 网络故障 | 服务离线时保留本地待处理任务 | 断网时保留队列，恢复后有限重试 |
| 更新传播 | 提交后通知本地页面 | 提交后通知有读取权限的在线页面 |
| 私有内容 | 按本地身份隔离 | 按已认证云端用户隔离 |

若本次选择两种模式或迁移，切换时保留账号、成员关系、历史周期和用量，不通过删除数据库重新建档完成迁移。迁移前后验证身份映射、数量及关键内容；持续双向同步属于额外明确选择的范围，不能默认承诺。

## 3. 身份、权限和账号关系

团队管理按本节及第 0 节确认的策略执行。本节默认基准是“团队业务账号均可查看、关联者和管理员可写、仅管理员调整成员”。若用户选择更严格的读取范围或指定管理角色，必须把已确认策略落实到所有相关入口；这是本次可选扩展分支，不声称原系统已经具备。个人管理使用稳定的本人身份及受控管理员初始化，保留关系模型和私有资源边界，按第 0.4 节简化人员管理流程与界面，不要求实现未选择的多用户操作流程。

### 3.1 多对多共同维护

- 同一账号可以由多人共同维护，同一人员可以维护多个账号。
- 使用 `account_members(account_id, user_id, display_name, position)` 关联表，用户 ID 来自可信身份目录或本地用户系统。
- 维护人姓名只用于展示，不参与身份授权；不得把外部服务账号 ID 填入系统用户 ID。
- 每个账号只保存一份额度、每日 Tokens、重置券和公共备注，不因关联人数增加而复制或重复统计。
- 账号成员名单有顺序，展示时保留；可以兼容旧的首位维护人字段，但权限判断必须读取完整成员表。
- 归档账号保留成员和历史数据。

### 3.2 权限规则

1. 默认所有正常登录、拥有应用访问权的用户可以查看全部团队业务账号；“与我相关”是页面筛选。选择“仅本人关联”或自定义分组范围时，后端按已确认读取策略限制所有查询及子资源，不能只做页面筛选。
2. 普通用户可创建仅本人维护的账号，并修改所有自己参与维护的账号及其额度、用量、公共备注和账号标签。
3. `accounts.manage_all` 权限点表示应用管理员，可维护全部账号、管理共同维护人、维护全局标签目录及导出授权范围内的完整业务数据。若选择“指定管理角色调整成员”，新增明确的受限权限点和账号范围，不为方便而直接授予全部管理权限。
4. 平台管理员或操作系统管理员角色不自动等于应用管理员。
5. 初始应用管理员由可信部署配置或显式的本地初始化流程确定，不自动授予第一位访问者。
6. 权限授予／撤销仅限人工管理员操作，需要目标、动作、当前版本、理由和短时一次性确认；禁止撤销最后一位管理员。
7. Agent 及跨应用代理不能通过权限接口自行提权。Agent 在已获授权的业务操作中沿用当前用户已有权限。
8. 普通采集不能调用成员管理和权限授予接口。
9. 成员变更成功后，被移除人员在下一次请求立即失去写权限；旧页面缓存不能维持权限。
10. 所有写入先读取当前资源再判断权限，不能依据请求体声称的属主判断。
11. 后端返回 `capabilities` 控制页面入口，服务端每次写入仍重新验证。

私人便笺、贴纸摆放位置、个人页面控制是例外的私有资源：应用管理员也无权越过当前用户访问或控制其他人的这些内容。

### 3.3 三种调用身份与 Agent 访问凭据

系统只接受三种调用身份，分别签发、分别校验，不能互相冒用：

| 身份 | 谁在用 | 怎么取得 | 能做什么 |
|---|---|---|---|
| 浏览器会话 | 用户本人在页面上操作 | 登录：个人本机为本地配对身份，云端为平台会话或独立认证会话 | 本人权限内的页面操作 |
| 设备采集授权 | 采集器、钩子和定时任务 | 设备首次配对时签发，走与 Agent 访问凭据相同的配对流程 | 只能提交已绑定账号的快照、查询本设备同步状态（第 2.2、9.1 节） |
| Agent 访问凭据 | 代表某位用户操作的 Agent | 用户本人在页面上批准后签发 | 本人权限内的业务读写，不能执行 human_only 动作 |

全文所说“获授权的 Agent”，指持有本节 Agent 访问凭据、代表某位用户操作的 Agent。没有这类凭据的 Agent 不能调用业务写入接口。

Agent 访问凭据的要求：

- 签发：Agent 发起配对申请后，页面显示申请设备、用途和一个短码；用户本人在已登录的页面上核对短码并点“同意”后才签发。设备采集授权走同一流程，由采集器的安装工具发起申请。用户也可以在页面“已授权的 AI”入口主动生成。Agent 不能自己批准，也不能用采集授权或浏览器页面凭据换取。
- 权限：不超过签发用户当前的权限，并随用户权限变化即时生效；不能调用权限授予／撤销、页面注册、页面 ACK 等 human_only 接口；可按需限定为只读。
- 保存：由安装工具写入本机系统凭据库（例如 Windows 凭据管理器、macOS 钥匙串、Linux Secret Service）；系统凭据库不可用时，写入仅本人可读的文件并记录这一降级。凭据不出现在聊天、日志、教程、安装包和任务正文里。
- 使用：提供一个稳定的本机调用入口，例如一个小命令行工具，由它读取凭据并调用接口；新的 Agent 会话按 GUIDE 使用这个入口，用户不需要复制令牌。
- 管理：设有效期并支持续期；页面“已授权的 AI”列出每个凭据的名称、设备和最近使用时间，用户可以一键撤销，撤销后下一次请求即失效。
- 审计：经 Agent 凭据完成的写入记录“哪位用户的哪个 Agent 凭据”，不记录私人便笺等正文。
- 个人本机模式同样需要这类凭据，不能因为服务只监听回环地址，就让本机任意程序免认证写入（见第 2.1 节）。
- 部署到已有应用平台、且平台本身提供可验证的 Agent 代理身份时，可以复用平台机制，但必须满足同样的权限上限、撤销和审计要求。

用户以后在任何新的 AI 会话里说“帮我改一下某个账号的到期日”，Agent 先读 GUIDE，检查本机是否已有有效凭据：有就直接办理并回读结果；没有就发起一次配对，请用户在页面上点“同意”，然后继续办理。

## 4. 数据模型和字段语义

### 4.1 账号

至少包含以下字段：

| 字段 | 含义与约束 |
|---|---|
| `id` | 应用内部稳定账号 ID |
| `provider` | 中性的服务类型键，来自可配置服务目录，不把类型写死成两个枚举 |
| `alias` | 必填，自定义账号名，1–120 字符；不是唯一身份 |
| `external_account_id` | 经核实的外部账号稳定标识；按第 8 节设计结构化绑定 |
| `email` | 实际邮箱，可空；不根据姓名或别的账号推测 |
| `display_identifier` | 页面展示标识，可独立于邮箱 |
| `port` | 可选整数 1–65535，仅作为业务标识，不自动探测或连接该端口 |
| `plan` | 实际套餐名称，未知时保持未知，不猜倍率 |
| `enabled` | 应用内启用状态 |
| `archived` | 归档／软删除状态，默认列表不显示 |
| `credential_status` | `available`、`needs_login`、`unknown` |
| `subscription_expires_at` | 本期套餐到期时刻，可空 |
| `subscription_checked_at` | 来源真实核实订阅信息的时间，可空 |
| `training_disabled` | `true` 已关闭聊天训练、`false` 未关闭、`null` 未知 |
| `coupons` | 可用重置券数；非负整数或未知，不用 0 代表未知 |
| `members` | 完整有序共同维护人名单 |
| `version` | 账号资源版本 |
| `created_at`、`updated_at` | 应用记录时间，不能冒充来源核实时间 |

展示标识根据服务配置及用户选择使用端口、显示标识或邮箱。内部 ID 不作为默认的可读主标题。同步默认保留 alias、端口、显示偏好、启用／归档状态、成员名单和人工确认设置。

### 4.2 额度窗口

同一账号可以同时拥有多个独立额度池，例如：

- 全部模型周额度：10080 分钟。
- 五小时额度：300 分钟。
- 专项模型周额度：同为 10080 分钟，但属于不同额度池。
- 其他来源真实提供的命名窗口与时长。

每条窗口保存：`id`、`account_id`、`name`、`pool_key`、`window_minutes`、`window_start_at`、`resets_at`、`remaining_percent`、`observed_at`、`period_anchor_at`、`version`，以及可选的历史合并标识 `merged_into`、`merge_conflict`。

- `pool_key` 是稳定额度池身份，显示名称和时长都不能单独充当额度池身份。
- 比例为有限数 0–100 或未知；如果来源给出已用比例，准确换算剩余比例，拒绝越界及 NaN。
- `window_start_at` 仅保存来源明确提供的准确起点；没有准确起点时允许页面根据重置时间和时长计算绘制位置，但不得伪造准确采集值。
- 窗口时长为正整数，支持至少 1–527040 分钟。
- 额度重置时间、套餐到期时间和登录凭据过期时间是不同字段，禁止互相代替。
- 旧周期结束后保留历史；没有新快照时不能自动恢复为 100%。

### 4.3 每日 Tokens

- 每个账号、每个来源日期保留一份当日绝对值，而非追加消费事件。
- 最少字段为 `account_id`、`usage_date`、`tokens`、`version`；来源范围、采集时间和完整性可在采集／同步记录中保存，便于判断覆盖条件。
- 日期为来源给出的 `YYYY-MM-DD`，不换算到另一时区，不给图表额外编造“统计从几点到几点”。
- `tokens=0` 是来源明确返回零；`null` 或缺失日期表示未知，两者不能混淆。
- 日值为非负整数，前端和接口必须防止整数精度损失。
- 默认接受范围不超过 `9007199254740991`；更大值必须有明确的大整数协议，不能转成有损浮点数。
- 不从额度百分比、生命周期总量或零散日志反推完整日用量。
- 本机局部用量不能覆盖账号级完整用量；覆盖关系不明确时保留原值并报告。
- 多设备观察到同一账号的完整日值时不能相加；只有来源能证明互不重叠的事件明细才可另行聚合。

### 4.4 重置券

除数量外保存完整明细快照：

```json
{
  "observed_at": "2026-10-26T14:00:00+08:00",
  "available_count": 1,
  "credits": [
    {
      "id": "credit-example-1",
      "reset_type": "quota_reset",
      "status": "available",
      "granted_at": "2026-10-20T12:00:00+08:00",
      "expires_at": "2026-11-01T12:00:00+08:00"
    }
  ]
}
```

上例仅说明结构。数量与明细不一致时必须提示“明细待更新”，不能自行补造缺少的券。正式测试数据应包含一致与不一致两类场景。

- 券 ID 不是兑换密码，禁止保存兑换密钥。
- `available_count` 可为未知；券 ID 在快照内唯一；到期不得早于已知发放时间。
- 来源没有返回明细数组时省略更新；明确返回空数组才表示确实无明细。
- 旧快照不能覆盖新快照，同一观测时间的冲突数据返回冲突。
- 倒计时不修改来源的券状态和数量，也不自动使用券。

### 4.5 三种文本／标记数据

必须明确区分：

1. 账号公共备注：每账号一份，最多 2000 字符，账号共同维护人与管理员可写，有业务读取权的用户可读。
2. 私人便笺：每用户一份，最多 10000 字符，仅本人及代表本人的获授权 Agent 读写。
3. 账号标签：目录和账号关联共享；是否画出贴纸是共享关联属性，贴纸拖动位置仅属于当前用户。

它们使用独立资源及版本，不把私人便笺混入账号备注、导出或公共通知。

## 5. 核心界面和交互

### 5.1 桌面周期日历

- 页面标题和浏览器标题统一为“AI账号管理”，使用简洁的 AI 主题 SVG 图标。
- 采用清晰、紧凑的浅色界面、精细边框和条纹行；图标使用 SVG，避免用表情符号代替功能图标。
- 左侧先显示账号邮箱／端口／展示标识，右侧显示共同维护人，后面接水平时间轴。
- 一个账号只有一个账号主体块；多额度池作为该账号内部的独立子轨道，不按维护人数复制账号。
- 多人姓名放大、加粗并保持可读；桌面账号主标识参考 16px、服务类型辅助文字参考 12px，不以增大行高破坏紧凑布局。
- 共同维护人区突出“我”，人数较多时提供查看全部入口，详情列出完整名单。
- 日期表头吸顶，左侧固定列与时间轴严格对齐，横向滚动时表头同步。
- 支持垂直浏览、水平拖动／滚动、Shift + 滚轮横移、前后翻页、“今天”和到期位置定位。
- 支持向时间轴两侧增量扩展历史／未来范围；后台单次查询范围受限时分段查询并完整读取分页。
- 周末、月份切换、今天及当前时间位置有明确视觉提示。
- 重新打开或重新显示页面时可靠定位今天，保留筛选、排序及缩放档位；页面隐藏导致尺寸为零时不得计算并保存错误日期位置。
- 滚动位置在后台刷新、筛选重绘和图表更新时尽量保持；“重新打开定位今天”优先于历史横向日期位置恢复。

### 5.2 多额度池与时间缩放

- 动态枚举真实额度池，每个池独立显示名称、剩余比例和重置时间。
- 提供“全部窗口”和逐池筛选；同名不同池要增加可辨认的辅助说明，不能误合并。
- 支持按天概览、按天放大、每格六小时、每格一小时四档显示，提供“天／小时”和加减按钮。
- 放大后五小时窗口必须能看清；缩放前后保持当前时间轴中心，避免跳回起点。
- 记住用户缩放偏好，手机按适合窄屏的宽度绘制。
- 一个窗口筛选条件不能让真实存在但没有该窗口的账号被伪造出窗口；空状态应明确。
- 默认周重置排序只使用明确的全部模型周额度；不能拿五小时窗口或专项模型周窗口冒充默认周额度。

### 5.3 额度和到期的视觉规则

- 整个周期条表示时间范围，填充长度表示剩余比例；已用区域与剩余区域有清晰纹理、边框区分。
- 剩余额度颜色连续呈现：高额度绿色、中间橙色、低额度红色，不经过紫色。
- 20% 及以下可有低额度提醒，但不能在阈值处突然换成完全不同的颜色。
- 未知比例使用明确的未知样式，不能画成零余额。
- 套餐到期在时间轴上使用独立标记，并与额度重置视觉区分。
- 套餐到期前三天强调提示；不到一天显示“不到1天到期”；已过到期日期显示“日期已过，待核对”，不能直接推断已续费或永久失效。
- 窗口结束仍无新数据时显示历史／待更新状态，保留真实更新时间。
- 悬停额度条显示贴近光标的小型换行提示，包含账号、维护人、窗口名、剩余比例、周期开始、重置时间和更新时间。
- 悬浮提示不放不可点击的“查看完整详情”按钮，不遮挡光标，不承担业务操作；在边缘自动避让，并支持键盘焦点对应提示。
- 用户界面使用“更新时间”等自然表达，不堆砌实现细节；准确来源与推算说明保存在字段和技术文档中。
- 悬停可有轻微提亮、阴影和柔和高光；尊重系统减少动态效果设置，不改变真实比例和时间几何位置。

### 5.4 筛选和排序

- 按服务类型筛选，切换“全部账号／与我相关”。
- 按额度池筛选；按标签筛选；支持标签反向筛选。
- 默认服务顺序来自可配置目录，再保持稳定的账号顺序，不能把任何具体服务名称写死进排序代码。
- 可按额度重置时间或套餐到期时间升序／降序排列。
- 日期排序是逐账号全局排序，允许同一维护人的账号出现在不同位置，不能为了按人员聚类打乱日期顺序。
- 未知时间始终排最后，正序和倒序一致；同时间使用稳定次序，数据刷新不能无故抖动。
- 筛选、排序、标签反向状态和缩放按应用与当前用户隔离保存。

### 5.5 账号详情

点击账号行或额度轨道打开详情弹窗，至少包括：

- 展示标识、服务类型、套餐、登录／启用状态。
- 全部共同维护人，以及当前用户“可维护／仅查看”状态。
- 每个额度池当前窗口及其独立剩余比例、开始／重置时间和更新时间。
- 每日 Tokens 图表及日／周／月切换。
- 本期套餐到期日、剩余时间与真实核实时间。
- 可用重置券数和独立“重置券信息”区块，按到期时间分组展示数量、到期时刻和向上取整的剩余天数；缺失日期明确未知。
- “是否关闭聊天内容用于模型训练”：是／否／未知。该记录不表示系统替用户改过第三方开关。
- 账号公共备注，支持输入、自动保存、保存中／已保存／冲突／失败提示和重试。

弹窗支持 Escape 关闭、合理的焦点限制及关闭后焦点恢复。已有备注未保存或保存结果不明时不能静默丢弃；用户主动关闭可按既定保存流程处理，Agent 页面控制不得触发这一隐式保存。

### 5.6 Tokens 图表

- 展示真实已录入数据，不使用随机曲线或样例数据混入生产。
- 支持日、自然周（周一开始）、自然月聚合，按保存的来源日期计算。
- 聚合同时返回已知总量、已知天数和未知天数；有缺失时显示“已知 X／N 天未录入”，不能把局部已知总量标成完整总量。
- 支持横向滚动历史、前后翻页、“最新”、柱状选中和精确数值提示。
- 显示当前可见日期范围；切换粒度保留各自滚动和选中状态。
- 支持方向键、Home、End 等键盘操作，动态刷新保留焦点。
- 读数可用 K／M 紧凑展示，悬停或辅助文本提供精确整数。
- 无数据、明确零、部分缺失和读取失败显示不同状态。

### 5.7 手机模式

- 保留日历形态，避免改成另一套复杂管理后台。
- 首屏重点展示账号、所选额度剩余及重置日期；默认使用明确的全部模型周额度。
- 隐藏共同维护人列、冗长套餐说明、复杂图例和自动同步接入按钮等次要内容；详细资料通过弹窗查看。
- 新增的额度池、缩放、标签筛选等保留必要入口，工具栏可横向滚动但页面整体不能溢出。
- 支持触摸横滑时间轴，贴纸和便笺适配触摸，不依赖鼠标悬停完成关键操作。
- 验证 320px、390px、430px 等窄屏尺寸和桌面尺寸；手机样式通过断点局部覆盖，不能破坏桌面布局。

## 6. 标签、贴纸与私人便笺

### 6.1 共享标签与私人摆放

- 账号支持多个标签，单账号最多 30 个。
- 标签分 `standard` 普通标签与 `person` 人名标签；人名标签属于固定“人名”类别，内容为实际姓名字符串，不能改变为任意自定义类别。
- 普通标签以简洁小贴纸图标显示，悬停显示名称，普通点击不弹出庞大详情。
- 人名标签直接显示较大的姓名文字，可在账号行内拖动。
- 所有贴纸可在所属账号整行的可用区域自由摆放，不增加账号行高；保存行内 0–1 归一化位置，布局变化后仍可恢复。
- 同一标签在不同账号的关联独立；摆放位置按“用户＋账号＋标签”保存，只影响本人。
- `visible=false` 仅隐藏贴纸，后台关联保留，仍参与分类和筛选；隐藏标签不是保密数据。
- 标签目录和账号关联共享，私人位置不能通过公共事件或其他用户响应泄露。
- 标签名做 Unicode NFKC、空白归一化和不区分大小写匹配，1–20 字符；同类型同名复用，不同类型可同名。
- 支持自定义颜色选择和输入 `#RGB`／`#RRGGBB`，保存为标准色值，自动选择可读文字颜色；不能只有几个写死颜色可选。
- 提供简洁的“＋ 贴标签”入口和适量编辑操作，不把贴纸变成完整表单列表。
- 可以只从当前账号移除标签，保留其他账号及目录；也可以由管理员全局删除标签，影响全部关联，包括隐藏关联和归档账号。
- 修改共享名称／颜色、全局删除与恢复仅限应用管理员；共同维护人可维护自己账号的关联。
- 两种删除都支持撤销。全局撤销只恢复该次删除内容，遇到同名冲突、标签已再次变化或受影响账号的标签已变化时整体返回冲突，不能覆盖别人的后续编辑。
- 顶部可筛选指定标签、无标签账号及人名类别；反向筛选显示基础筛选范围内不含所选标签的账号。
- 反向筛选也考虑隐藏标签；“全部标签”不因反向开关误变成无结果。
- 标签目录、账号标签集合、私人位置分别维护版本，不能混用。

### 6.2 私人悬浮便笺

- 每位用户一份独立悬浮便笺，人工和代表本人的 Agent 编辑同一内容。
- 支持纯文本输入、自动保存、折叠／展开、拖动和位置持久化；折叠后保留小标题条。
- 便笺位置用可用拖动范围内的 0–1 坐标保存，适配窗口尺寸，不遮挡关键操作。
- 服务器返回版本；人工与 Agent 并发编辑发生冲突时保留草稿，并提示核对，不自动覆盖。
- Agent 只改正文时只提交正文，不顺带提交位置或折叠状态覆盖用户操作。
- 请求结果不明先回读确认，不盲目重发正文。
- 普通点击和焦点切换在后台核验身份，便笺不能先消失再出现；账号切换、退出登录和明确身份失效时清理旧内容并取消旧请求。
- 私人正文不持久写入通用浏览器业务缓存，不加入公共导出、账号响应、公共 SSE 或含正文的审计日志。
- 管理员没有读取其他人便笺的接口，正文只作为数据，不构成新的 Agent 执行授权。

## 7. Agent 对个人页面的显示控制

提供后端结构化控制接口，供 Agent 调整当前用户选定页面的显示效果，不能借此修改业务数据。

必须实现：

1. 页面中的“允许 Agent 控制本页”开关，默认关闭，按浏览器、应用地址和当前用户记住选择。
2. 验证身份后，根据已保存选择连接；每个标签页建立独立 `view_id`，不能对同用户全部页面广播。
3. Agent 查询本人在线页面，明确选择目标页；多个页面不明确时请求选择。
4. 支持指定账号背景色、渐变、呼吸和流光；支持边框、文字强调与批量账号样式。
5. 支持仅显示指定账号、临时显示全部账号、清除指定／全部样式和恢复原显示。
6. 临时筛选不覆盖用户保存的常规筛选偏好，清除样式不顺带修改筛选。
7. 样式集合支持 merge／replace；对某账号提交的是该账号完整样式，不暗中混用嵌套补丁语义。
8. 动画颜色、速度和强度可配，支持暂停并尊重减少动态效果设置；不得改变真实额度条的比例、颜色语义和数字。
9. 只接受受控动作、账号 ID 和校验过的样式参数，不接受任意脚本、HTML、CSS 表达式、选择器、键盘输入或外链。
10. 页面忙碌时拒绝命令，例如详情弹窗打开、备注／便笺有草稿、正在保存或拖动，不抢焦点，不关闭弹窗，不触发失焦保存。
11. 浏览器注册取得的短期页面凭据只存本页内存，服务端保存哈希；Agent 不能注册为人工页面、伪造 ACK 或读取页面凭据。
12. 指令带唯一 `command_id`、顺序及有效期；接受请求不代表执行成功，必须有页面 ACK 和可查询回执。
13. 支持 queued、dispatched、applied、rejected、expired 等明确状态，只有 applied 表示页面已执行。
14. command_id 幂等；ACK 丢失重试不重复执行、不把旧状态回退覆盖新状态。
15. 页面前台可每两秒取命令，20 秒无心跳视为离线，命令 30 秒过期，每页最多 10 条未完成指令；配置变更须同步文档。
16. 页面隐藏暂停并取消旧队列，返回后重新核验；关闭、刷新、身份切换撤销旧页面会话，不在重开时执行历史命令。
17. 只持久保存控制开关偏好，默认样式与临时显示集合只在本页内存；用户可一键暂停或恢复原显示。
18. 不复用向所有业务阅读者广播的变更通道发送页面控制指令。

颜色最少支持合法十六进制；动效参数参考：周期 2–30 秒、强度 0.1–0.6、每页最多 100 个账号样式。支持能力通过协议版本和 GUIDE 公布，旧客户端不应静默接受不支持的新动作。

## 8. 本地数据采集、触发和账号匹配

按已确认的设备、操作系统、来源和触发策略实现。云端管理同样依赖本地采集，但不意味着必须额外交付本地管理应用；也不因存在多个系统说明就默认制作所有操作系统的安装包。只选择报告／表格导入且真实自动采集尚未纳入当前阶段时，明确当前边界；选择“仅定时”时复用后台采集与传输规则，不安装未启用的 Hook。

### 8.1 可扩展采集适配器

设计统一的适配器接口，包括：

```text
detect_environment()
get_capabilities()
read_identity()
collect_snapshot(requested_fields)
validate_identity_before_after()
```

按实际授权使用本机 CLI／本地进程 RPC、正式账号接口、用户允许访问的账号页面，或本机已经存在的缓存／统计文件。先识别操作系统、运行时、工具版本及能力，不照搬另一机器的绝对路径。

支持两类采集策略：

- 实时查询型：独立获取当前身份及额度，查询前后核对账号一致。
- 缓存观察型：检查本机额度缓存更新，根据真实缓存采集时间／业务内容判断是否有新数据，不把文件读取时间伪装成新观测时间。

接口能力与安装版本有关。读取不到数据时区分：来源未提供、当前版本不支持、权限不足、缓存陈旧、请求失败、尚未查询、用户排除。不能把“尚未查询”报告成“不可获取”。

采集和传输不调用语言模型，不额外发起 AI 会话，不消耗重置券，不发送业务提示词给模型。

### 8.2 采集范围

按可得能力逐组检查：

- 当前外部账号稳定 ID、邮箱、服务类型、套餐和可验证的登录状态。
- 订阅开始／到期信息及来源真实核实时间；数据模型未承接的字段保留在标准快照中，不擅自填入其他字段。
- 所有真实可得的额度池及其时长、剩余比例、准确起点、重置时刻和观测时间。
- 重置券数量及逐张明细。
- 来源真实提供的逐日 Tokens、日期范围和统计覆盖范围。
- 训练设置仅在实际可核实或用户明确提供时记录，其他情况保留已有人工值。

不要因为当前已有脚本只解析周额度，就遗漏可得的五小时或专项模型额度；也不要因前端支持某窗口就伪造来源没有提供的记录。

### 8.3 Hook 和后台执行

本节事件入口要求适用于已选择 Hook 的分支。定时任务分支复用身份核对、单实例锁、队列、采集和回读逻辑；是否创建实际定时任务及具体时间按第 0 节确认的策略执行。

- 适配宿主支持的“会话启动／恢复”和“本轮回答结束”等事件，事件名称通过适配器映射。
- Hook 本身只解析必要事件类型、登记待处理任务并唤醒后台程序，快速返回，不同步等待网络上传。
- 输入明确按 UTF-8 处理，覆盖中文路径、引号、反斜线及无效输入；不要依赖系统默认编码。
- 不保存或上传 Hook 载荷中的聊天正文、工具输入、转录路径或项目内容。
- 单机同一采集身份使用进程锁，多个项目、会话触发合并，避免同时启动多个采集任务。
- 实时查询型适配器默认最少 30 分钟进行一次实际采集尝试，可配置。冷却期保留最后一次待处理触发，到期后重新采集，不能把旧快照冒充当前数据。
- 缓存型适配器默认在有新缓存时上传；这是不同规则，不能统一宣称所有工具都严格每 30 分钟触发。
- 区分“收到事件”“执行采集”“提交数据”（直传快照或上传报告文件）“应用入库”；每一步都有自己的时间和结果。
- 触发间隔和内容去重分开实现：内容去重比较账号、额度池、余额和重置时间等业务字段，不把本次生成时间作为数据变化依据。
- 业务值未变化时可保留心跳／新鲜度记录，但不能伪造来源核实时间；策略在文档中明确。
- 在用户选择定时补漏时实现该能力，与 Hook 共用采集、锁、去重和发送逻辑；任务目标与时间已明确且获得创建授权时实际配置，否则仅交付配置入口并标记未启用。
- 无待处理触发时后台程序退出；需要等待冷却时使用轻量等待或持久任务机制，并说明资源使用情况。
- 电脑休眠、关机、客户端未运行或需要信任钩子时明确提示，不能保证不具备运行条件时仍实时同步。

### 8.4 账号识别、首次认领及切换

建议实现独立 `account_bindings` 表，记录账号、服务类型、外部稳定账号 ID 及已确认的必要组织／工作区维度。唯一约束必须基于实际身份作用域设计，不能仅用姓名、端口或同一邮箱粗暴合并。

匹配流程：

1. 验证当前管理系统身份，完整分页读取其参与维护的候选账号，同时检查相关归档记录以防重复建档。
2. 读取采集前的外部账号身份，采集后再次核对；切换或身份冲突时停止本次写入。
3. 存在已确认的结构化绑定时，复核绑定与成员关系后更新原记录。
4. 没有绑定但存在唯一可靠候选时，按证据核对；邮箱可辅助匹配，但不能忽略组织身份冲突。
5. 旧记录缺邮箱、标识不全或同一人有多个候选时，展示名称、端口、套餐和到期日供用户选择一次，不要求用户手填内部 UUID。
6. 用户认领后在原账号补充绑定，保留显示偏好、公共备注、历史用量及其他成员。
7. 候选都不是当前账号且用户明确要求新增时才创建；认不出来时保持未绑定，不自动猜测、新建、合并或转移。
8. 后续自动运行复用确认绑定，除非身份或权限发生变化，不反复要求认领。

若兼容旧项目曾将绑定存放在备注，迁移前解析固定格式并核对唯一性；不能丢弃用户原备注。新实现优先结构化存储，不把备注继续当作主要身份数据库。

### 8.5 来源探测与核实（给 AI）

接真实数据前，按下列步骤找到并核实数据来源。探测全程只读。

1. 先看附录 A。清单不为空时，核对本机工具版本是否在清单的适用范围内：在范围内就按清单读取，再做第 4 步核实；不在范围内或清单为空，继续第 2 步。
2. 列出这台设备上用户实际在用的 AI 工具（命令行工具、桌面应用、编辑器插件）及版本，用一句大白话请用户确认要接哪些（见第 0.1 节“检测后确认”）。
3. 对每个要接入的工具，按以下顺序查找数据，找到可靠的就停：
   - 工具自带、可以非交互调用的用量／额度／状态命令；
   - 官方公开的账号或用量接口；
   - 工具在本机配置目录里保存的结构化缓存或统计文件，查找含剩余比例、重置时间、窗口时长、每日用量、账号标识等字段的文件；
   - 用户已有的采集脚本或钩子：只读，先弄清它从哪里取数。
4. 每个来源都要核实并写清：
   - 数据属于哪个账号（身份字段），采集前后能否核对；
   - 覆盖范围：账号总量还是仅这台设备；
   - 时间字段的含义：来源观测时间、缓存写入时间还是文件修改时间；
   - 至少一次与工具自身界面显示的数值对上；无法打开界面时如实说明。
5. 把结果写进 `project-config.md` 的“来源适配记录”：工具和版本、读取方式（命令，或相对工具配置目录的位置）、字段对应关系、覆盖范围、核实方式和时间、已知限制。不写凭据和具体账号数据。
6. 只读边界：不修改工具配置，不登录或登出，不额外发起 AI 会话，不打印凭据文件内容（凭据文件只判断是否存在）。本机缓存格式属于工具内部细节，可能随版本变化；采集器要校验结构，遇到不认识的格式就停止写入并报告，不猜测解析。
7. 找不到可靠来源时，用大白话告诉用户卡在哪，并给出可选办法：先导入表格、先用模拟数据把系统跑通，或者由用户提供已有脚本。不能用猜测的位置或格式冒充已接入。

## 9. 上报协议、云端中转和入库可靠性

统一快照、账号校验、周期去重与可靠性规则适用于全部已选模式；简报解析和云端文件入库任务仅在选择报告中转时实现。未选择中转时无需搭建文件收集区、扫描器或报告回填 Agent。

### 9.1 统一 JSON 快照

本地直传和云端直传使用同一结构，以下为虚构示例：

```json
{
  "schema_version": "1.0",
  "snapshot_id": "snapshot-example-001",
  "device_id": "paired-device-example",
  "provider": "service_a",
  "external_account_id": "external-account-example",
  "collected_at": "2026-10-26T14:00:00+08:00",
  "source": {
    "kind": "local_cli",
    "adapter_version": "1.0.0",
    "coverage": "account_total"
  },
  "account": {
    "email": "user@example.invalid",
    "plan": "基础套餐",
    "credential_status": "available"
  },
  "quota_windows": [
    {
      "pool_key": "all_models_weekly",
      "name": "全部模型周额度",
      "window_minutes": 10080,
      "remaining_percent": 54,
      "resets_at": "2026-10-30T15:30:00+08:00",
      "observed_at": "2026-10-26T14:00:00+08:00"
    }
  ],
  "daily_usage": [
    {"usage_date": "2026-10-25", "tokens": 123456}
  ],
  "collection_results": [
    {"group": "subscription", "status": "source_not_provided"},
    {"group": "reset_credits", "status": "source_not_provided"}
  ]
}
```

协议要求：

- 未获得字段省略，而非填空字符串、0 或 null 覆盖已有有效值；诊断数组单独说明缺失原因。
- 可声明来源的真实观测／核实时间；服务器另记 `received_at`，不可互换。
- `device_id` 和快照中的身份声明只用于核对，最终归属来自已验证的设备授权和绑定。
- 若允许 `user_id`，它只是核对声明，必须与服务端认证映射一致，不能靠修改请求体成为另一用户。
- 设置载荷大小、数组条数、时间格式及数据类型限制；未知结构版本不能继续猜测解析。
- 不包含账号密码、Cookie、访问令牌、认证文件正文、聊天内容和私人便笺。
- 同一个 `snapshot_id` 重发必须保持业务内容一致，同 ID 不同内容返回冲突。
- 整体接收状态与各字段实际写入结果分开返回，可查询处理明细。

### 9.2 兼容简报文件

仅在需要兼容已有四行简报采集器时实现解析；新建的中转路径直接上传第 9.1 节的 JSON 快照文件，不再生成四行简报。四行简报格式如下，用中性服务键区分来源：

```text
邮箱：user@example.invalid
周额度剩余：54%
重置时间：2026/10/30 15:30:00
更新时间：2026/10/26 14:00:00
```

- 文件名形如 `service_a-user-20261026-140000.txt`，只保留到秒；通过禁止覆盖、存储对象 ID 或安全后缀解决同秒碰撞。
- 明确约定该简报时间为北京时间；缺少时区且不符合约定的其他格式不能自行猜测。
- 四行简报只能更新其实际提供的邮箱及周额度信息，不能据此声称已采集套餐、重置券和每日用量。
- 简报对应的额度池必须由已确认的来源协议指定，不能把任意周额度都归入全部模型额度。
- 报告保留原始采集时间；文件上传时间和修改时间不代表数据观测时间。

### 9.3 云端文件入库任务

- 中转文件优先是第 9.1 节的 JSON 快照，入库时走与直传相同的快照处理逻辑，不另写一套解析和入库规则；四行简报先转换成快照结构，再进入同一流程。
- 增量发现新增／变更报告，以对象标识、版本和内容哈希建立处理台账；维护可恢复游标并处理分页和延迟到达文件。
- 队列状态至少区分待解析、待认领、处理中、已成功、部分成功、可重试失败和不可重试失败。
- 多任务并发时使用原子领取／锁或等价机制；同一文件多次发现不重复入库。
- 无唯一绑定、格式无效、权限不足或身份冲突的报告保留并标记，不自动新建账号，也不无限重试。
- 记录每个报告对应哪些账号、额度周期及日用量发生变化；全部处理结果可追溯。
- 检查上传回执中的路径／对象 ID、版本和内容哈希，有条件时回读内容核对。
- 若上传已确认但回读不可用，明确记录“上传已确认，回读暂不可用”，不能称完整链路已验证。
- 报告上传成功不等于应用入库成功，更不等于浏览器已执行更新。
- 已保存报告可作历史审计，但不因回放历史文件回退业务最新数据。

### 9.4 同周期额度去重

这是必须在后端保证的核心规则，不能只要求 Agent 自觉遵守。

1. 按账号、稳定额度池、窗口时长与固定周期锚点匹配。
2. 重置时间距原固定锚点不超过 60 秒可视为同周期，处理秒级／分钟级来源精度差异；阈值可配置并需验证。
3. 锚点一旦确定不随每次上传移动，避免多次小幅漂移最终跨周期。
4. 同周期更新原窗口；只有真实新周期才新增窗口 ID。
5. 两个不同额度池即使时长和重置时间相同也保持独立。
6. 同时到达的两个写入必须通过数据库事务和并发控制避免重复记录。
7. 新观测更新已知值；旧观测不覆盖更新的已知值；同一观测时刻不同有效值返回冲突。
8. 新报告余额未知／缺失时，不能抹掉已知余额，也不能把旧余额时间推进为本次观测时间。
9. 当前余额未知时可接纳较早的真实有效余额，同时保存该值真实观测时间。
10. 多个匹配候选、池映射冲突或历史合并冲突时停止该窗口写入，不换池键规避。
11. 历史重复数据通过有备份、可审计的迁移／修复处理，保留原始行及 `merged_into`，正常查询排除已合并原行。
12. 写旧合并 ID 返回明确错误和 canonical ID，调用方先回读，不盲目重放。
13. 原子 upsert 返回成功甚至 201 不代表一定新增，必须通过资源 ID、版本和明确的 created／updated／unchanged 结果判断。

### 9.5 幂等、版本与重试

- 新增账号和窗口必须提供 `Idempotency-Key`；同用户、同操作、同键同载荷返回相同操作结果，同键不同载荷返回 409。
- 幂等记录保留至少 24 小时；版本控制和业务去重不能由幂等键替代。
- 账号、额度、每日 Tokens、公共备注、标签和便笺分别使用自己的 `expected_version`。
- 新日用量／未创建备注／便笺可从版本 0 开始；冲突后读取最新状态并按意图合并，不能只换版本重试。
- 同一次失败重试复用原幂等键和业务载荷；采集到新快照则使用新的快照身份。
- 网络超时、TLS 短断连、临时 503 和限流可有限退避重试；401／403、绑定歧义和数据冲突需要停止相应写入并说明原因。
- 响应丢失导致结果不明时先查资源／同步记录，确认未生效再决定是否重试。
- 本地队列使用原子写文件或事务保存，进程崩溃后恢复；重试已确定账号的旧快照时仍使用原绑定，不能按此时切换后的账号重新归属。
- 跨多个业务接口的同步不默认具有一个总事务。返回每项结果，部分成功必须如实显示；可在新快照处理服务内部实现明确的原子边界。
- 事务提交成功后才能返回业务成功、更新处理台账和发送变更通知。

## 10. 后端 API 和 Agent 使用说明

### 10.1 通用约定

- 所有业务入口位于 `/api/`，身份只来自第 3.3 节的三种调用身份：可信浏览器会话、受限设备采集授权和 Agent 访问凭据。
- 成功统一返回 `data` 和包含 `request_id`、`server_time` 的 `meta`。
- 错误统一返回 `error.code`、`message`、`retryable`、必要且脱敏的 `details`，以及 `meta`。
- 时间点使用带时区的 RFC3339，数据库统一保存可比较的时刻；页面额度、套餐及券时间默认以 `Asia/Shanghai` 展示。
- 日期范围统一左闭右开；日历单次最多 366 天，日用量单次最多 400 天，超过时分段读取。
- 分页游标绑定筛选条件，筛选改变必须重新分页；调用方不能只拿第一页就宣称“全部账号”。
- 未授权、参数非法、版本冲突、临时故障使用清晰 HTTP 状态与错误码。
- 输入严格限制额外字段，错误响应不回显可能误提交的敏感值。

### 10.2 必须提供的业务接口

以下为完整接口基准。个人模式按第 0.4 节省去仅供多人管理的成员及权限维护流程；其他核心业务能力保留。若已有项目保留这些接口，必须继续校验权限，不能通过隐藏入口替代保护。

| 方法 | 路径 | 能力 |
|---|---|---|
| GET | `/api/me/permissions` | 当前身份及应用权限 |
| GET | `/api/accounts` | 分页查询，支持服务、成员、搜索、启用和归档条件 |

| GET | `/api/accounts/calendar` | 指定日期范围的账号及额度窗口 |
| GET | `/api/accounts/{id}` | 详情、版本、成员、窗口、备注和操作能力 |
| PATCH | `/api/accounts/{id}` | 局部更新元数据，含归档／恢复 |
| GET／PUT | `/api/accounts/{id}/members` | 查看／管理员替换有序共同维护人 |
| GET／POST | `/api/accounts/{id}/quota-windows` | 查询／原子新增或更新窗口 |
| PATCH | `/api/accounts/{id}/quota-windows/{window_id}` | 指定窗口更正与版本保护 |
| PUT | `/api/accounts/{id}/usage/daily/{date}` | 当日绝对 Tokens 值 |
| GET | `/api/accounts/{id}/usage` | 日／周／月统计及原始日版本 |
| PUT | `/api/accounts/{id}/note` | 保存或清空公共备注 |
| GET | `/api/accounts/export.xlsx` | 管理员完整导出 |
| GET | `/api/tags` | 共享目录、关联及仅本人摆放位置 |

| POST | `/api/tags/{tag_id}/restore` | 版本受控的全局撤销 |
| PUT | `/api/me/tag-placements/{id}/{tag_id}` | 仅本人贴纸位置 |
| GET／PATCH | `/api/me/personal-note` | 仅本人便笺 |
| GET | `/api/events` | 提交后的业务变更提示 |
| GET | `/api/permission-grants` | 管理员查看权限记录 |

私人便笺 PATCH 要求 `X-Expected-User-ID` 与最近核验的本人身份一致，仅作为身份断言，不用它选择属主；不接收任意 owner 参数。标签修改也应有等价的身份切换保护。

### 10.3 本次通用化新增的接入接口

以下路径是本次开发建议的明确协议，可以按框架调整命名，但必须交付等价能力并写入 GUIDE：

| 方法 | 路径 | 能力 |
|---|---|---|
| GET | `/api/providers` | 可配置中性服务目录及适配能力 |
| GET／POST | `/api/accounts/{id}/bindings` | 已认证范围内查询／确认绑定，禁止采集器随意认领 |
| POST | `/api/ingest/snapshots` | 本地／云端统一快照接收 |
| GET | `/api/ingest/snapshots/{snapshot_id}` | 可见范围内的处理结果与每项回读状态 |
| GET | `/api/me/sync-status` | 本人设备最近触发、采集、上传、入库及失败情况 |
| POST | `/api/pairings` | 采集器或 Agent 发起配对申请，注明申请设备采集授权还是 Agent 访问凭据，返回短码和查询地址 |

接收接口不是账号全权限写入入口，必须限制允许字段和已授权绑定。除设备采集授权外，也接受代表本人的 Agent 访问凭据提交快照（仅限本人参与维护的账号，来源标记为“Agent 代录”），供第 13.4 节的应急路径使用。

个人页面控制最少提供 `/api/ui/views`、`/api/ui/commands`、`/api/ui/commands/{command_id}`，以及浏览器专用的注册、取命令、ACK、暂停／撤销入口。浏览器与 Agent 的身份能力必须分开校验。

### 10.4 集中维护的 GUIDE

`GET /api/agent-guide` 必须由当前实现自动维护或与代码同时更新，包括：

- 版本号、更新时间、支持的协议版本及兼容要求。
- 身份与权限、human_only 动作、各资源字段和版本语义。
- 本地／云端模式、数据采集边界、来源能力探测及字段完整性检查。
- 账号匹配、首次认领、成员关系和绑定冲突处理。
- 额度周期去重、过期值保护、每日 Tokens 绝对值规则。
- 标签、人名贴纸、私人便笺、导出和个人页面控制的完整接口。
- 幂等、重试、结果不明处理、写后回读与完成报告样例。
- Agent 访问凭据：怎样检查本机是否已有有效凭据、怎样发起配对、本机调用入口的用法、凭据失效或被撤销时怎么办；这部分在未认证时也可读取。
- Agent 安装、配对、Hook／定时配置、首次真实同步及页面验证的执行规范；稳定的接入说明入口、组件版本、状态查询和中断后继续办法。需要先认证才能读取完整 GUIDE 时，安装前的非秘密说明和登录配对入口应可取得，不能形成“必须已安装才能知道怎么安装”的循环。

首次配置、人工同步和每次自动任务执行均读取最新版 GUIDE，记录版本及读取时间；旧实现不能兼容时停止写入并报告。

安装教程和定时任务仅保留稳定入口指令，不能把完整规范长期复制在每个人的 HTML 或任务正文里，导致修改后必须重新分发全部材料。

## 11. 实时更新、缓存与异步一致性

- 事务提交后通过 SSE 提示业务资源变化，浏览器再调用正常 GET 读取数据。
- 公共通知只带资源类型，不携带账号内容、备注正文、私人便笺或个人位置；读取范围受限时，通知路由也遵守已确认访问策略，不泄露无权资源的变化。
- 每进程共享数据库监听连接，通道按环境／数据库隔离，不为每个浏览器单独占用一个数据库监听。
- 云端 PostgreSQL 可用提交后通知，本地 SQLite 使用服务内提交事件及重同步机制；多进程部署必须有可靠跨进程通知方式。
- SSE 心跳参考 15 秒，连接定期重新认证；断流时释放旧连接并回退到约 15 秒的 GET 轮询。
- 页面隐藏时暂停订阅及轮询，返回、网络恢复或事件 resync 时重新同步。
- 后台更新要真正重新请求数据，不能只更新时间文字、重绘旧数组冒充自动同步。
- 业务缓存按应用地址与已验证用户隔离；先核验身份再恢复缓存，先展示已有缓存再后台更新。
- 账号日历、详情和 Tokens 分开缓存，详情与用量可并行请求；参考上限 24 小时、48 条缓存，支持清理。
- 缓存不能授予编辑权限；登录失效、用户切换时清理旧用户数据。
- 更新保留筛选、排序、滚动、图表选中、焦点及未保存草稿。
- 防止旧请求晚到覆盖新筛选、新账号或新身份；使用取消请求、请求代次和版本校验。
- 刷新失败保留可用旧数据并提示真实更新时间；不能把缓存或网络失败显示成当前实时结果。

## 12. 导出、导入和历史保留

### 12.1 完整 Excel 导出

由 `accounts.manage_all` 控制，人工及该用户获授权的 Agent 可调用。导出不受页面筛选、分页、“与我相关”或当前显示额度池限制。

至少提供六张工作表：

1. 账号清单：未归档账号，包括已过期、停用账号。
2. 已删除账号：实际为归档／软删除账号，保留原信息。
3. 账号人员关联：每个账号与维护人一行，包括归档账号的现存关系。
4. 额度窗口：有效历史、合并原行及合并状态。
5. 每日 Tokens：来源日期、绝对值与未知状态。
6. 重置券明细：逐张信息和快照时间。

要求：

- 使用数据库一致性快照，成员数量变化不影响账号额度及 Tokens 总量。
- 全部维护人及其 ID 可查看，按某个人筛选使用关联表。
- 日期时间默认北京时间，日用量日期原样保留。
- 支持冻结表头、筛选、条纹、到期提示和清晰列宽。
- 业务文本按文本写入，防止公式注入；超过表格整数精度的数值以文本保真。
- 超过行数／文本容量明确报错，不静默截断。
- 返回真实 XLSX 二进制附件，禁止将错误 JSON 保存成伪 XLSX。
- 不导出凭据、页面令牌、权限确认、私人便笺或其他人私人位置。
- 不声称恢复数据库中已不存在的物理删除历史。

### 12.2 批量导入能力

提供可供 Agent／管理脚本使用的结构化导入流程，不要求在主页面增加繁复上传表单。

- 支持从表格整理账号信息、匹配可信人员目录、预览差异、确认后调用业务 API。
- 预检报告列出明确可导入、标识缺失、可能重复、人员匹配不唯一和日期有歧义的记录。
- 明确标记废弃的来源账号按任务要求跳过；已有归档历史不因未出现在新表中被删除。
- 单独保留 email、display_identifier 和 port，不能用新邮箱覆盖用户指定端口展示。
- 只提供日期而无时刻时，要求配置明确的日期录入约定；若采用北京时间当天 23:59:59，要保留说明，不能无声推定。
- 缺年份、带问号、无效日期、含义不明确的“共享数据”等字段保留待确认，不猜测。
- 不导入表格中可能含有的密码／令牌，不通过导入修改成员或权限来绕过授权。
- 已有较新有效数据优先保留，导入后报告实际新增、更新、跳过及冲突数量并回读核验。

## 13. 技术架构、安装和运维交付

### 13.1 默认技术方案

若分发者随本文提供了已测试的参考实现或安装包，先核对来源、版本和校验值，以它为基础安装和配置，只补齐所选分支缺少的部分并按第 14 节验证，不重新从零开发；参考实现与本文冲突时，说明差异并按本文修正。

从零开发按所选范围采用下列对应组件，不因为提供了两个数据库或两个部署方案就默认实现两套：

- 前端：React、TypeScript、Vite，配合轻量样式方案；如果启用会重置原生样式的框架，必须验证其没有破坏日历和弹窗。
- 后端：Python Web API 框架和严格请求模型，拆分身份适配、领域服务、数据库访问、导出、通知和接入处理。
- 本地采集器／Hook：Python 或等价轻量运行时，跨平台入口与后台 worker 分离。
- 本地数据库：SQLite，使用事务、外键和版本控制；云端数据库：PostgreSQL，使用约束和并发保护。
- 业务逻辑只实现一份，数据库特定代码放适配层；单模式只实现所需数据库适配，也必须遵守相同的权限、去重、新鲜度及事务规则。
- 页面、业务 API、采集入口和文件中转 worker 各自清晰分层；无需为这个系统引入无关的多个前端壳应用。

若部署到已有应用平台，使用平台标准身份与数据库注入机制，不再创建多余登录系统；独立云部署需要交付等价的认证、会话和人工管理员初始化能力。

### 13.3 Hook 安装和升级

- 为用户确认的目标系统实现可重复执行的安装入口，随后由 Agent 在目标设备实际运行，而不是只告诉用户双击或粘贴命令。Windows、其他系统分别使用可用的原生入口；先检查运行时、宿主能力和登录状态，只处理已选系统。
- 先检查是否已安装、版本和连接是否正常，能复用就复用；Agent 按需要获取可信安装材料、核对版本与校验值、安装依赖、执行安装、读取结果并检查实际配置。
- 运行时和依赖优先使用现有可用环境或隔离环境，不为安装小工具随意升级用户全局环境、覆盖其他项目配置或修改无关 Hook。
- 首次完成配对后，正常运行无需手填邮箱、余额、GUID 或保存路径。
- 对宿主 Hook 配置做原子合并，保留原有钩子和未知字段；重复安装不重复增加条目。
- 安装／卸载共用配置锁；仅能证明原进程已退出时恢复遗留锁，不能删除归属不明的锁。
- 需要本人重开 AI 工具、登录或信任钩子时，Agent 只说明现在必须操作的界面和完成标志，保存进度后等待；用户完成后继续检查钩子加载和真实触发，安装器不代替用户绕过信任。
- 提供状态检查：版本、最近触发、待处理任务、最近采集、上传／入库／回读及固定错误码。
- 诊断日志有限大小轮转，只记录事件名、时间、阶段与必要错误码，不包含聊天和凭据。
- 支持有明确版本和校验值的原位升级；需要更新的已授权目标由 Agent 实际执行升级并复测。替换云端下载包只影响之后获取，不声称其他设备已自动升级。
- 如实现自动升级，必须有独立、可验证、可回退的更新协议并明确实际支持范围；不要把未实现的自动升级写成现有能力。
- 用户要求卸载时由 Agent 执行，只删除本包可识别的 Hook，停止后续任务，保留用户数据／历史和必要备份；已发出的网络请求可能完成，状态需如实说明。
- 分别报告各操作系统的实际验证范围，不能用一套离线测试冒充所有系统的实机验证。

### 13.4 应用内接入教程

- 桌面提供简洁“让 AI 帮我接入／自动同步接入”入口，按来源与目标系统展示带办说明，不以“下载后自行安装”作为主要路径。
- 主流程为“把接入任务交给设备上的 Agent → Agent 检查并安装 → 用户完成必要登录／授权／信任 → Agent 自动继续配置和验证 → 显示已接入结果”。安装包下载作为备用分发入口，不是要求用户掌握的操作步骤。
- 提供可复制的简短接入指令或当前环境确实支持的“一键交给 Agent”动作。只能声称工具实际支持的能力；复制一段文字不能假装已经启动另一台设备的 Agent。
- 接入指令引用稳定的、已验证的安装说明和在线 GUIDE，要求 Agent 实际执行下载、安装、配置、首次采集、上传回读及页面验证。开发交付时填入真实目标入口，不让用户自己拼服务地址、账号 ID 或下载路径。
- 显示真实包版本、运行前提、校验值、最近更新及未验证的平台限制。
- 使用稳定下载入口更新安装包版本，同时显示真实包内版本，避免名称与内容长期不一致。
- 说明“已触发／已上传／已入库／已读回”的差异及两类采集策略，不把缓存刷新周期写成 Hook 触发周期。
- Agent 先检查已有连接，正常则复用；不让已配对用户反复安装或生成新凭据。
- 没有本机接入工具时，优先由 Agent 安装可用的接入工具；确无适配工具但用户已同意应急路径时，由本地 Agent 采集非凭据快照，用第 3.3 节的 Agent 访问凭据直接提交到快照接收接口，再按最新版 GUIDE 读回核对，不让用户手工抄写账号数据，不提取浏览器会话秘密。
- 教程只承诺实际已验证能力，不把应急浏览器操作承诺为无人值守后台同步。

### 13.5 部署与运行

- 本地／内网分支由 Agent 实际准备环境、初始化数据库、配置访问、启动服务并打开页面；云端分支由 Agent 通过已授权平台工具或服务器通道完成构建／上传、配置、迁移、启动及健康检查。只处理已选分支，双模式按确认顺序分别完成，不能把发出镜像或部署包当作部署结束。
- 实际运行目标若未接通，先尝试现有可信入口并检查具体原因，完成不依赖该目标的准备；只在确需用户连接或授权时请求那一步。接通后由 Agent 接着部署，不改成让用户按一整份手册自行安装。
- 安装后检查实际监听地址、运行进程、数据库连接、页面入口、登录和业务接口。正式使用应有符合运行环境的进程托管及启动／恢复方式，不把随一次终端退出而消失的临时进程冒充完成安装。
- 数据库迁移递增、可追溯，执行后验证，不在普通应用启动中偷偷删表／重建库。
- 云端环境区分调试和正式数据库，测试样例不进入生产。
- 备份包括数据库和必要配置，恢复步骤验证账号、绑定、历史和用户隔离，不导出明文凭据。
- 前端资源及 API 路径必须兼容平台入口、认证回调和桌面客户端；固定根路径部署使用 `/assets/` 与 `/api/`，不要因相对路径把资源请求到认证回调子目录。
- 若支持路径前缀部署，使用显式配置并测试真实入口；JS 资源返回 HTML 时必须可定位为资源路由错误，不能只留下白屏。
- 应用显示名称、SVG 图标和浏览器标题保持一致；部署到已有平台时，平台上的应用名称、图标等展示信息若无法由 Agent 设置，如实说明限制，不误报已登记成功。
- 提供结构化日志和健康信息，区分数据库不可用、身份失效、采集失败、上传失败、入库失败及前端资源故障。
- 使用受限设备授权和安全凭据存储，不把个人长期全权限令牌硬编码进可转发安装包；演示配置只用占位符。
- 不默认开放远程终端、任意命令执行或第三方账号登录代理。

### 13.6 Agent 亲自执行的全流程带办清单

本节是实施流程，不是仅生成教程的写作任务。完成范围确认后，Agent 必须逐步实际执行，并为每一步记录目标、结果和下一步。可以组合工具调用，但不能省略关键核验。

| 步骤 | Agent 必须亲自做什么 | 用户只在确有必要时做什么 | 完成证据 |
|---|---|---|---|
| 1. 核实目标 | 检测系统、源码目录、已有服务、依赖、已安装组件和连接通道；判断命令究竟在哪台机器运行 | 确认无法推断的目标或接通指定设备 | 实际目标、环境、版本和可执行通道已核实，已有可用组件复用 |
| 2. 建好并装好管理系统 | 开发、构建、准备依赖、执行迁移、写入目标配置、启动服务；已有系统先备份本次会修改的必要配置和数据 | 通过真正要求本人的平台／系统审批 | 服务在指定目标运行，数据库连接正常，真实入口能访问 |
| 3. 建立登录与设备连接 | 检查已有登录和配对；通过安全机制完成授权接入，把真实应用入口及受限授权写入适当位置；为本机 Agent 发起配对并取得 Agent 访问凭据（第 3.3 节） | 本人登录、扫码或批准配对；不在聊天中粘贴秘密 | 会话身份和设备映射已核实，授权范围符合选择，Agent 凭据已存入系统凭据库并能完成一次读取，秘密未出现在日志和教程中 |
| 4. 安装读取小工具 | 获取或构建采集器、核验材料、在目标设备运行安装、设置路径及运行环境、检查命令能执行 | 仅批准系统确实拦截的安装动作 | 实际安装路径、版本、可执行入口及自检结果，而非只有压缩包 |
| 5. 配置自动更新 | 按选择合并安装 Hook、后台 worker 和／或定时任务，填写真实目标，验证限频、锁和配置；保留已有钩子 | 宿主强制要求时信任指定钩子或重开工具 | 钩子实际被宿主加载，或定时任务已登记且参数正确；未选功能未启用 |
| 6. 采集当前账号 | 按第 8.5 节探测并核实数据来源；在目标本机识别当前账号，核对采集前后身份，读取实际可得资料、额度池、券和每日用量；按范围确认认领并保留人工字段 | 仅在绑定歧义时选择已有记录 | 有真实来源、观测时间、字段完整性及缺失原因的快照，不用模拟值冒充 |
| 7. 上传并实际入库 | 通过所选直传／中转通道发送；检查回执；中转时实际启用并检查统一处理任务；按账号与周期去重写入 | 必要的目标系统审批 | 上传结果、处理结果、目标账号及资源 ID、版本可核对；不能只停在收集区有文件 |
| 8. 读回并检查页面 | 用业务接口读回关键字段；实际打开应用页面，检查账号、额度、日期、用量与快照一致，并验证已打开页面的自动更新 | 如浏览器未登录，仅完成本人登录 | 来源快照、接口读回及页面显示三者一致；没有浏览器能力时明确页面尚未验证 |
| 9. 检查后续还能运行 | 验证一次真实宿主事件／定时执行，检查后台恢复、队列及最近同步状态；测试重复发送不重复入库，保留正常限频规则 | 只能由用户触发的最小操作，例如完成一轮正常使用 | 已触发、已采集、已上传、已入库、已读回分别有实际记录；仅手动运行脚本不能证明钩子已生效 |
| 10. 带用户验收 | 展示真实可用入口、当前结果、自动更新时间、最少日常操作及故障时如何叫 Agent 处理 | 看结果、试用并反馈 | 按配置核对的验收记录及仍需处理的具体事项 |

执行要求：

- 命令由 Agent 的终端、平台工具、已授权远程通道或目标设备上的 Agent 实际运行，不只输出代码块让用户复制。运行后查看退出状态及实际服务／文件／配置，退出码 0 不替代完整联调。
- 安装器保留适合自动化的非交互入口、状态查询及可机器读取的结果，必要参数由 Agent 从已确认配置获取；不要让无人值守执行卡在“按任意键继续”。面向用户的安全确认不能被自动化入口绕过。
- 授权、接入码或令牌按实际安全机制处理，不能因为用户不想手工安装就把长期高权限凭据写进可分发包。
- 需要用户介入时按“现在卡在哪里 → 请只做哪一步 → 完成后 Agent 怎么接着做”说明。例如：“小工具已经装好，还需要你在 AI 工具里点一次信任。点好告诉我，我会检查触发并继续上传。”不要把所有剩余步骤变成用户任务。
- 需要用户点“允许”或输入系统密码时，先用一句大白话说明这一步要做什么、为什么需要；用户拒绝后换用不需要该权限的做法，或说明不做会有什么影响，不反复发起同一个请求。
- 遇到依赖、路径、编码、端口、网络短断连或可恢复服务错误，Agent 先定位并在既有授权内修复、重试和验证，不因普通报错直接把技术排查交给用户。改变数据去向、身份范围、破坏已有运行环境或扩大真实发布范围时另行确认。
- 必须重启当前会话依赖的宿主、导致控制通道暂时断开时，先保存无秘密的进度和继续入口；告知用户必要的一次操作，重连后检测实际状态并从未完成步骤继续，不让用户重新描述整个项目。
- 多台设备分别安装，维护逐设备状态。当前 Agent 有可信执行通道时直接操作；没有时，为该设备上的获授权 Agent 提供稳定接入指令和共同的版本化说明，由它实际执行并回传可核验结果。无法触达的设备保持“待连接”，不能在当前机器运行一次就宣称所有员工设备已安装。
- 后续运行以确定性采集器和后台程序为主，不因“由 Agent 带办”改成每轮都新建 AI 会话调用模型采集。Agent 负责实施、必要调整和排错，日常更新由已装好的程序完成。

### 13.7 保姆级教程：一份给用户，一份给 Agent

在实际项目中生成并维护以下三类资料；教程必须与已安装版本、真实路径和当前运行状态一致，不能只复制通用步骤。

**A. 给普通用户看的新手使用教程**

- 用本提示词“问法要求”的大白话，只讲用户要做的最少事情：选择使用方式、必要时登录／授权／信任、查看结果、以后怎样叫 Agent 帮忙。
- 不要求用户理解服务端、数据库、运行时、端口、接口参数和幂等规则；这些由 Agent 检测、填写和执行。
- 不把“下载若干包、选路径、手工改配置、复制命令、找日志”写成默认用户操作链。安装包是备用材料，不是主要交付体验。
- 每一步写清“Agent 已经做了什么／接下来会做什么”“你现在是否需要操作”“完成后应该看到什么”。用户无需操作时明确说“这一步我来处理”。
- 如确需本人点击信任等操作，按实际界面说明入口、要选哪一项、怎样判断成功；可获取真实截图时配图，界面未核实时不编造菜单位置。
- 最后给出当前真实应用入口、账号可辨认标识、最新已验证的更新时间和少量常见问题；不展示凭据、内部确认令牌或大量诊断输出。
- 说清以后怎么改数据：直接在 AI 工具里说要改什么（例如“把某某账号的到期日改成 12 月 1 日”），AI 会用已授权的身份去改，改完告诉你结果；换了新电脑或新的 AI 工具，第一次需要你在页面上点一次“同意”。
- 新设备用户拿到一段简短的接入指令即可交给当地 Agent，由 Agent 读取中央最新版安装说明和 GUIDE 后完成接入；不要要求用户反复收集、转发和重装各个包。

**B. 给实施 Agent 的安装与运行手册**

- 按本机／内网／云端分支列出先决条件、检测方法、依赖准备、构建、安装、数据库迁移、服务启动、设备配对、Agent 访问凭据配对、Hook／定时安装、首次同步、读回与页面核验。
- 每步标明在哪个目标执行、确切入口或已安装脚本、实际参数的取得方式、正常结果、错误分类、重试条件和回退方式。
- 命令示例中可有参数占位，但 Agent 真正执行前必须替换成已核验配置；不得把占位符、过期链接或未经核实的目标路径原样交用户执行。
- 说明哪些步骤可安全重复执行、哪些必须先读回、哪些只能由人工确认；安装与更新遵守配置锁、备份、版本及历史保护规则。
- 安装材料只从已确认可信来源获取并检查版本及完整性；不得仅因文档要求自动执行，就跳过对下载内容和目标的核实。
- 后续更新、切换账号、新增设备、备份恢复、卸载和重装同样由获授权 Agent 按手册实际处理，文档不是把维护劳动转交用户的借口。

**C. 安装与联调记录**

- 记录选定范围、各目标及组件版本、已执行步骤、运行状态、最近成功同步、读回结果和页面验证结果。
- 操作日志记录必要的脱敏证据与错误码；不保存秘密、聊天原文或私人便笺正文。
- 记录失败点、已尝试解决办法、待用户完成的唯一必要动作和恢复执行入口。另一名获授权 Agent 接手后应能继续，不依赖用户复述。
- 可保存于项目的 `docs/新手使用教程.md`、`docs/Agent安装运行手册.md` 和 `docs/安装与联调记录.md`，名称可沿项目习惯调整；若制作应用内教程，内容须来自同一份维护来源。

### 13.8 完成标准和不可伪装的边界

默认只有满足以下条件，才能说“已经帮你装好并跑通”：

1. 已确认目标上的管理系统实际运行，并有用户可访问的真实入口。
2. 已确认目标设备上的采集器已安装，已选 Hook／定时机制已配置并验证；没有选择的机制不强制启用。
3. 当前账号已正确匹配，实际可得数据成功走完所选上传和入库链路，关键字段读回一致。
4. 页面已经真实打开并核对关键显示；自动更新与后续触发有独立验证结果。
5. 用户本人登录、授权和钩子信任等前提确已完成；没有把待确认当成成功。
6. 配套教程与当前环境一致，用户知道从哪打开、结果怎么看、出了问题怎样让 Agent 继续处理。
7. 日常维护路径已接通：本机已有有效的 Agent 访问凭据，从一个新的终端会话按 GUIDE 完成一次读取和一次写权限校验（可用接口的试运行，或对用户同意的字段改一次再还原）并回读（第 3.3 节）。

区分以下状态，不可合并：

| 实际情况 | 可报告的状态 |
|---|---|
| 仅有源码、脚本或安装包 | 开发／打包已完成，安装未完成 |
| 服务已启动，采集器尚未接通 | 系统已运行，自动采集待接入 |
| 采集器已装，宿主尚未信任或未验证事件 | 安装已完成，自动触发待确认／待验证 |
| 数据已提交或报告已上传，应用没有读回 | 已上传，入库或回读待验证 |
| 仅有模拟数据或静态截图 | 隔离流程／界面预览通过，真实链路未通过 |
| 接口一致，但没有实际打开页面 | 数据读回通过，页面呈现待验证 |
| Agent 访问凭据未建立或未验证 | 系统可查看，经 Agent 的日常维护待接通 |
| 指定设备无连接、缺权限或未在线 | 该目标待连接／待授权，其他已通过目标单独报告 |
| 全部适用项完成且有证据 | 指定范围已安装、已接通并验证可用 |

用户暂时无法提供必需环境或实际授权时，完成可独立推进的工作，明确阻碍和继续入口。只有用户明确将当前阶段改为“仅准备／仅打包／仅方案”时才按缩小范围交付，仍不可宣称原先的全流程目标已经完成。

## 14. 必须通过的验证场景

根据已确认范围运行有意义的测试，覆盖以下适用场景并提供结果。未选择的模式／上报路径／团队流程标记“不适用”，不能列成开发缺失；已选择但未执行、只能模拟或未有实机环境的检查必须单独说明。

### 14.0 选择流程与范围一致性

- 用户没有提供配置时，AI 实际调用可用的内置选择框，首轮只问管理方式和部署方式（项目起点能从用户消息或当前目录判断时不问），不先生成代码或部署；不把文字列表或工具 JSON 冒充弹窗。
- 按第 0.1 节问法分级：检测后确认类只用一句话请用户确认检测结果，默认值类写进汇总、不逐题问；个人＋本机的常见情况，开工前一般不超过 3 轮、5 道题（含最后确认）。
- 内置选择工具不可用时明确说明并回退编号选项，不调用不可用工具、不为显示弹窗强制改变会话模式。
- 每批问题服从实际工具能力；单选不能假装多选，预选与超时不算回答，异步提问必须等待实际结果。
- 选择框标题、选项、每轮小结、配置摘要、冲突说明和验收结果都用大白话，不懂技术的人也能看懂；不展示问题 ID，术语不裸露，口语说法与对应配置值含义一致。
- 已明确“个人＋本地”时只补问相关环境，不要求配置公司人员目录和云端服务器。
- 选择“个人＋云端”时保留多设备采集能力，不自动启用团队成员管理流程。
- 选择“团队＋本地”时启用团队权限和内网设备接入，不把团队强制改成云端部署。
- 选择“团队＋云端”时确认身份来源及上报路径，未选中转不搭建文件扫描任务。
- 用户明确选择双模式／双路径时才交付并验证两者；已经提供并确认的信息不反复询问。
- 核心功能基准与已选范围一致，个人模式仍包含多个账号、完整日历、标签、便笺和用量能力。
- 仅定时不安装实际 Hook，仅 Hook 不创建补漏任务；自定义周期不能超过来源或运行平台的实际能力。
- 团队读取范围和管理角色选择贯穿 API、统计、标签、导出、缓存和事件验证，不能只修改界面。
- 更改上游选择后，只重问失效的下游项；配置摘要、建议默认值、真实环境缺口和最终确认一致。
- 接入缺失、失败、未验收和不适用分别记录；用户选择“需要调整”后修复并重验，未答复不等于验收通过。

### 14.1 业务与权限

- 普通用户按已选策略读取业务账号，只能写参与维护的账号；默认共享策略和选定的受限策略分别按适用范围验证。
- 非首位维护人同样可写；成员被移除后立即失去写权限。
- 管理员可管理成员和导出，平台角色本身不能越权；Agent 不能提权，最后管理员不可撤销。
- 同一账号多人关联不导致额度、Tokens 或导出总量重复。
- 同时修改账号／备注／标签／便笺发生版本冲突，原数据和草稿不被静默覆盖。
- 私人便笺、贴纸位置和页面控制不被另一用户或管理员越权访问。
- Agent 访问凭据只能经本人在页面批准后签发；权限不超过本人并随本人权限变化；不能调用 human_only 接口；撤销后下一次请求即失效；采集授权和浏览器页面凭据都不能换取 Agent 凭据。

### 14.2 数据真实性和去重

- 同周期多次报告只更新一个有效窗口，新周期才新增。
- 两个并发新增、秒级时间精度差、连续漂移、相同时间不同池、同时间冲突和已合并旧 ID 都得到正确结果。
- 旧观测不回退新余额，未知不清除已知，新未知不伪造观测时间。
- 日用量重复 PUT 不累加；零、未知、局部统计和账号完整统计分别正确处理。
- 重置券空数组、明细缺失、数量不一致、过期倒计时及旧快照得到正确处理。
- 无邮箱旧账号认领后复用原 ID，账号切换不串号，歧义不自动创建。
- 六张导出表包含归档和合并历史，不含私人内容，精度和文本写入正确。

### 14.3 Hook、传输和中转

- UTF-8 中文、引号、反斜线、无效事件、超大输入及空输入不会静默掩盖必要诊断。
- 多会话同时触发只运行一个 worker，冷却期最后事件保留，无任务退出。
- 实时型与缓存型按各自规则执行；定时补漏与 Hook 不重复运行。
- 本地服务停止、云端断网、TLS 短断连、限流、进程中断及恢复后队列可继续。
- 上传响应丢失、已上传但回读失败、已上传但未入库、部分入库分别有真实状态。
- 文件重复发现、内容版本变化、分页、延迟文件及多 worker 竞争不造成重复业务记录。
- 云端和本地都不接受伪造 user_id／device_id 绕过绑定，不泄露认证内容。
- 设备采集授权只能经本人在页面批准后签发；撤销后该设备下一次提交即被拒绝，本地待发队列保留数据并提示重新配对。
- 选择报告中转时，同一份快照经直传和经中转入库的结果一致（共用同一套处理逻辑）。

### 14.4 前端和页面控制

- 桌面固定列、吸顶、横向表头对齐、全局日期排序、未知排末及今天定位正确。
- 页面隐藏后重开不跳到过去错误位置；筛选和缩放记忆保持。
- 周额度、五小时、专项周额度独立显示，日／小时缩放保持中心。
- 标签显示／隐藏、正反筛选、人名文字、自定义颜色、拖动、两种删除与撤销正确。
- 私人便笺人工和 Agent 双向同步，焦点变化无闪烁，冲突保留草稿，切换身份清空旧内容。
- SSE 提交后通知、回滚无通知、断线轮询补偿、恢复重连和旧异步响应隔离正确。
- 有缓存时先显示，身份失效清缓存；刷新不覆盖备注和便笺草稿。
- 页面控制只作用选定本人标签页，回执 applied 才算成功，忙碌拒绝，过期不重放，重复 ACK 不重复执行。
- 320／390／430px 手机无整体溢出，桌面样式保持；键盘、触摸与减少动效可用。
- 真实认证入口／回调路径可以正确加载脚本、样式和接口，不出现相对路径白屏。

### 14.5 两种模式的端到端验收

仅验收已选模式和路径；双模式或双路径才要求分别完成。每条验收都必须说明是否使用真实来源、隔离测试或模拟传输。

本地模式完成一次真实或明确标记为测试的；团队内网把“本地直传”替换为“成员设备直传内网服务”：

`事件 → 采集 → 本地直传 → 数据库 → API 读回 → 已打开页面自动更新`。

云端直传路径完成：

`事件 → 采集 → HTTPS 直传 → 入库 → 读回 → 页面更新`。

云端报告中转路径完成：

`事件 → 报告上传 → 云端发现 → 匹配与业务 API 回填 → 读回 → 页面更新`。

测试适配器可以使用隔离的中性样例数据验证协议，但不能把这种验证写成已经兼容任意实际服务。对接实际来源时必须验证对应适配器的采集能力和身份一致性。

### 14.6 Agent 亲自安装与保姆级体验验收

- Agent 确实在已确认的设备／平台执行安装和启动，记录目标及结果；不能只有构建成功、包下载成功或输出一段安装命令。
- 未安装场景完成依赖准备、安装、配置及自检；已安装场景复用正常连接，重复安装不增加重复钩子、不破坏旧设置。
- 服务、采集器、Hook／定时机制分别检查，安装器成功和手动采集成功不能互相替代，也不能替代宿主真实触发验证。
- 验证从必要用户授权处恢复：Agent 保存进度，用户只完成登录／配对／信任之一，Agent 继续接入和联调，用户不用重走整套安装步骤。
- 安装后普通路径、权限、依赖或短暂网络故障由 Agent 排查；不可恢复或缺少本人授权时，只请求真正必要的一步，不发整套手工排查清单代替工作。
- 至少一个实际目标按“部署运行 → 采集器安装 → 已选钩子／定时配置 → 真实账号采集 → 上传入库 → 接口读回 → 页面显示”核验；不具备真实来源时保留未完成项，不能以样例数据验收通过代替。
- 对照源快照、入库字段和页面逐组验证；来源无法取得的字段如实缺失，不能为了看起来全流程成功而补造数据。
- 团队接入逐设备核验，未连接设备明确待接通；本机安装一次不能算所有设备已安装。新用户可交给该设备上的 Agent 带办，不需要自己理解压缩包和脚本参数。
- 教程中的真实入口、版本、已安装路径和状态与当前环境一致；给普通用户的说明保留大白话，仅保留必须本人操作的步骤。
- 重新连接或重新打开管理页面后服务和业务数据仍可用；在所选运行方式支持的条件下检查后续触发和重连，不把暂时运行误报为长期可用。
- 最终报告区分开发完成、已安装、已触发、已上传、已入库、已读回和页面已验证；没有执行证据的阶段不能标成功。
- 从一个新的终端会话，按 GUIDE 用已登记的 Agent 访问凭据完成读取和写权限校验，证明用户以后换一个 AI 会话也能让 Agent 维护数据，不需要重新安装或复制令牌。
- 真实来源的读取方式、字段对应、覆盖范围和核实方式已写入“来源适配记录”，并至少一次与工具自身界面显示的数值一致。

## 15. 最终交付格式

按第 0 节确认的范围完成实际安装与联调后交付，顺序以用户能直接使用为先：

1. **已装好系统的真实入口和当前状态**：告诉用户从哪里打开、这次接通了哪些设备与账号、最新数据截至何时；无法完成的目标单独列出，不能混入成功清单。
2. **完整流程的实际证据**：按设备记录部署、采集器安装、已选 Hook／定时配置、采集、上传、入库、读回和页面呈现结果，注明具体缺失和已采用的真实／隔离验证范围。
3. **给普通用户的保姆级教程**：按第 13.7 节编写，只保留必要的本人操作、查看入口和日常使用；常规安装、配置、排错和维护由 Agent 继续负责。
4. **给后续 Agent 的实施手册和进度记录**：真实配置、版本化安装规范、继续入口、逐步核验、错误恢复与维护流程，不含秘密。
5. 完整源码、数据模型和迁移、身份与权限配置、已确认的项目范围记录，只包含所需分支。
6. 所选范围的业务 API、接入 API、页面控制协议、中央 GUIDE、采集器、Hook／worker／定时任务和状态工具。
7. 需要分发或备份的安装包、组件版本和校验文件作为配套产物；明确已由哪个 Agent 在哪些目标实际安装，不以包链接代替安装结果。
8. 对应模式的启动／停止、备份恢复、更新、卸载、迁移及故障排查资料，以及仍存在的具体阻碍和由 Agent 接着处理的方式。

给用户的最终说明使用大白话，优先说明“已经帮你装在哪里、现在能看到什么、以后怎么自动更新、还剩哪一步需要你本人确认”。不要以“这里有几个安装包，请自行安装”收尾，也不要用一大段用户必须手工执行的命令替代实施。

在交付前按范围记录和第 13.8 节完成标准逐项核对，不得把核心业务功能，以及本次选择的团队能力、部署、采集器／钩子安装、配置、上报路径和页面验证以“后续可扩展”或“用户稍后自己安装”代替实现。未选分支列为“不适用”；确有环境或授权限制时，明确说明已选范围内的未完成项、证据和继续入口，不编造成功结果，也不单方面缩小任务。
